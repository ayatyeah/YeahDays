# YeahGrind — PWA, разделы и уведомления

Пакет изменений: приложение перестаёт быть набором страниц и становится
оболочкой с разделами, кэш и установка доведены до нормального PWA, к утренним
и вечерним напоминаниям добавлены уведомления по ходу активной задачи.

Архив накладывается поверх репозитория `ayatyeah/YeahDays` — структура папок
совпадает, файлы заменяются целиком.

---

## 1. Что нужно сделать руками после копирования

```bash
npm install                 # зависимости не менялись, но prisma generate нужен
npx prisma generate
npx prisma db push          # появилась таблица ScheduledNotification
npm run typecheck           # ожидается: чисто
npm test                    # ожидается: 134 теста зелёные
npm run build
```

### Переменные окружения

Новых обязательных нет. Уже используемые остаются нужны:

| Переменная | Зачем |
| --- | --- |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` | подписка на push в браузере |
| `VAPID_PRIVATE_KEY` | отправка push с сервера |
| `VAPID_CONTACT` | контакт в VAPID (`mailto:`) |
| `CRON_SECRET` | защита `/api/push/send` и нового `/api/push/dispatch` |

Без VAPID-ключей приложение работает полностью, молчат только уведомления.

### Крон

К существующему часовому крону добавляется минутный:

| Расписание | Запрос | Зачем |
| --- | --- | --- |
| `0 * * * *` (уже есть) | `POST /api/push/send` | утро и вечер |
| `* * * * *` (новый) | `POST /api/push/dispatch` | «время задачи вышло», «через 5 минут дело» |

```bash
curl -X POST https://<домен>/api/push/dispatch \
  -H "Authorization: Bearer $CRON_SECRET"
```

Минутная сетка нужна именно для точечных напоминаний: «время вышло в 14:37» —
это про 14:37. Если минутный крон недоступен, поставь раз в 5 минут: в
`/api/push/dispatch` есть окно опоздания `GRACE_MS` (10 минут), просроченные
уведомления оно доберёт, но точность просядет.

## 2. Разделы вместо страниц

Маршруты `/app`, `/today`, `/calendar`, `/progress`, `/account` остались —
по ним приходят deep-link из уведомлений и ярлыков манифеста. Но теперь каждый
из них рендерит одну и ту же оболочку `AppShell`, а тела экранов переехали в
`src/sections/*`.

Внутри приложения переключение вкладки **не является навигацией**: меняется
видимый раздел, адрес обновляется через `history.pushState`. Отсюда следствия:

- разделы монтируются один раз и остаются в дереве — возврат мгновенный,
  состояние экрана и позиция скролла сохраняются;
- нет запроса RSC-пейлоада и повторной гидратации на каждый тап;
- работает свайп между разделами (кроме зон с `data-no-swipe` — колода);
- «назад» в браузере проходит по вкладкам, потому что каждое переключение —
  запись в истории.

Что важно не сломать при доработках:

- новые экраны приложения добавляются в `src/lib/nav.ts` (`TABS`, `TAB_PATH`)
  и в `SECTIONS` внутри `AppShell.tsx`;
- внутренние переходы между вкладками делаются через
  `useNavStore().go("today")`, а **не** через `<Link href="/today">` —
  иначе вернётся полноценная навигация;
- горизонтальные жесты внутри новых компонентов нужно помечать
  `data-no-swipe`, иначе они начнут листать разделы.

## 3. PWA

- `public/sw.js` переписан: отдельные кэши для оболочки, неизменяемых
  ассетов сборки и картинок; навигация — сеть с таймаутом 3.5 с, дальше кэш,
  дальше `/offline`; включён navigation preload; кэши подрезаются по размеру;
  `/api/**` и RSC-пейлоады не кэшируются никогда.
- `public/manifest.webmanifest`: `id`, `display_override`, `launch_handler`,
  `handle_links`, скриншоты для богатого диалога установки, три ярлыка.
- `next.config.ts`: заголовки кэширования для манифеста и статики,
  `optimizePackageImports`, снят `X-Powered-By`, базовые security-заголовки.
- `src/app/offline/page.tsx`: офлайн-заглушка без единого клиентского скрипта.
- Background Sync: воркер будит приложение, когда сеть вернулась, и очередь
  событий уходит на сервер (`EventFlusher`).

Обновление версии по-прежнему работает через `?v=<BUILD_ID>`: новая сборка =
новый кэш, `skipWaiting` только по кнопке «Обновить».

## 4. Уведомления

Три слоя, выбирается доступный:

1. **Notification Triggers** (Chrome/Android) — уведомление ставится прямо в
   систему, работает при закрытом приложении и без сети.
2. **Серверный web-push** (iOS 16.4+, Firefox, десктоп) — момент показа держит
   `/api/push/dispatch`.
3. Утро и вечер — прежний `/api/push/send`, теперь с учётом настроек и тихих
   часов.

Первый и второй слой взаимоисключающие: где есть триггеры, серверные копии не
создаются, поэтому одно событие = одно уведомление.

Что присылается по ходу задачи (`src/lib/notifyPlan.ts` — чистые правила,
покрыты тестами):

| Момент | Условие |
| --- | --- |
| половина времени | только для задач от 20 минут |
| время вышло | по заявленной длительности |
| дольше плана | `+max(10 мин, половина плана)` |
| задача висит | через 3 часа после взятия |
| дело со временем | за 5 минут до начала |

В уведомлении о задаче есть кнопки **«Сделал»** и **«+10 мин»**. «Сделал»
закрывает задачу, не открывая приложение (если вкладка закрыта — открывает
`/app?do=complete&task=<id>` и закрывает сразу после гидратации).

Настройки — в профиле: раздельные тумблеры (ритм дня / ход задачи / дела со
временем), тихие часы и кнопка «Проверить». Настройки лежат в `notify` внутри
стора и синхронизируются между устройствами; версия persist поднята до 13,
миграция для старых аккаунтов включает всё по умолчанию.

## 5. Как проверить руками

1. **Разделы.** Открыть с телефона, потыкать нижнюю навигацию: экраны меняются
   без белых вспышек, скролл каждого раздела свой. Свайп влево-вправо листает
   разделы; на колоде свайп по карточке по-прежнему «беру / не беру».
2. **Deep-link.** Открыть `/progress` прямой ссылкой — приложение стартует
   сразу на нужном разделе, без кадра главной.
3. **Офлайн.** Открыть приложение, включить авиарежим, перезапустить — экраны
   открываются, отмеченные задачи сохраняются, при возврате сети события
   уезжают на сервер.
4. **Установка.** Chrome DevTools → Application → Manifest: скриншоты, ярлыки
   и иконки без предупреждений. Lighthouse PWA — без ошибок.
5. **Уведомления.** Профиль → «Включить напоминания» → «Проверить» (должно
   прийти сразу). Затем взять действие на 1 минуту и свернуть приложение —
   через минуту придёт «Время задачи вышло» с кнопками.
6. **Кнопка «Сделал».** Нажать её в уведомлении — задача закрывается, XP
   начисляется, экран «Сегодня» это показывает.

## 6. Известные ограничения

- iOS присылает push только **установленному** приложению (добавленному на
  домашний экран) и начиная с iOS 16.4. В Safari-вкладке уведомлений не будет —
  это ограничение платформы, а не кода. В настройках есть поясняющая строка.
- Notification Triggers — только Chromium. Везде остальное точность зависит от
  частоты крона.
- Тихие часы считаются по часовому поясу устройства из `tzOffset` подписки;
  при перелёте они актуализируются при следующем открытии приложения.
