# YeahDays

**«Tinder твоих действий»** — не habit tracker со списком из 50 задач,
а ежедневная подборка нескольких действий под твоё текущее состояние.

Приложение отвечает на один вопрос:
> Какое маленькое действие сегодня максимально приблизит меня к лучшей версии себя?

---

## Что изменилось в этой версии

| Было | Стало |
|---|---|
| Список задач на главной | **Tinder-колода**: свайп вправо — беру, влево — не сейчас |
| Задача = название + сложность | 7 параметров: category, difficulty, duration, energy, timePreference, impact, why |
| Нет рекомендаций | **Scoring-движок** + backend API под будущий ML |
| 3 стата (Тело/Разум/Дисциплина) | **4 стата**: Сила, Интеллект, Капитал, Стабильность |
| PNG-персонаж + гардероб | **3D-персонаж на Three.js**, тело — функция статов |
| 4 экрана | **5 экранов**: Home, Today, Calendar, Progress, Profile |

### Движок рекомендаций

```
taskScore = goalMatch + timeMatch + difficultyMatch + userHistory + freshness
```

| Компонент | Вес | Что учитывает |
|---|---|---|
| `goalMatch` | 0.30 | приоритеты пользователя + отставание стата + impact |
| `timeMatch` | 0.20 | время суток + бюджет минут |
| `difficultyMatch` | 0.25 | энергия сегодня vs требуемая |
| `userHistory` | 0.15 | принял / отклонил / довёл до конца |
| `freshness` | 0.10 | антиповтор показов |

Каждая карточка показывает **почему** её предложили — это строится
из максимального компонента скоринга.

### Подключение настоящего бэкенда

Контракт уже готов. Переключение — одна переменная:

```bash
NEXT_PUBLIC_ENGINE=remote npm run build
```

Тогда `fetchRecommendations()` пойдёт в `POST /api/recommendations`,
а свайпы начнут писаться в `POST /api/events` (обучающая выборка).
Если сеть упадёт — движок автоматически считает локально, экран
не остаётся пустым.

## 3D-персонаж

Риггованная модель с настоящим скиннингом (`SkinnedMesh`, 66 костей
Biped: позвоночник, ключицы, руки с пальцами, ноги, стопы).
1470 треугольников, 90 КБ.

> **Атрибуция.** Модель «Rigged Man» — автор Mr.Toadstool (Sketchfab),
> лицензия **CC BY 4.0**. Лицензия разрешает коммерческое использование
> и модификацию, но **требует указания авторства** — оно выведено на
> экране «Профиль». Подробности: `public/models/CREDITS.md`.

### Статы меняют телосложение через кости

В GLB нет анимационных клипов — только скелет в bind-позе. Поэтому
позы и движение авторятся процедурно по костям (`lib/avatarPose.ts`),
а телосложение задаётся масштабом костей (`lib/avatarRig.ts`).

Ключевая особенность рига: **все кости вытянуты вдоль локальной X**
(у каждой `child.position = [len, 0, 0]`). Значит `scale.x` — это
длина кости, а `scale.y/z` — обхват. Соответственно «поднять руку» —
вращение вокруг **Y**, а не Z.

| Стат | Влияние |
|---|---|
| **Сила** | длина ключиц (ширина плеч), обхват груди/рук/ног, сужение талии и таза, осанка, развод рук |
| **Интеллект** | яркость ядра в груди |
| **Капитал** | пояс на тазовой кости, корона на кости головы |
| **Стабильность** | кольца платформы, разворот стоп |

V-образность, измерено по вершинам **после скиннинга**
(плечи t≈0.75, талия t≈0.55, без вершин предплечий и кистей):

```
новичок  lvl1  плечи=0.484 талия=0.351 → V = 1.38
середина lvl18 плечи=0.715 талия=0.330 → V = 2.17
прокачан lvl48 плечи=0.926 талия=0.313 → V = 2.96
```

### Анимация

Каждый кадр поза считается заново: кость сбрасывается к bind-базе
и домножается на смещение, поэтому состояния плавно смешиваются
без `AnimationMixer`.

- **Idle** — дыхание (грудь + ключицы), перенос веса с ноги на ногу,
  слежение головой за курсором, пульс ядра
- **Победа** — подскок, руки вверх, сгибание локтей, вспышка ядра
  (габарит модели 3.40 → 4.32, руки реально поднимаются)

Поза покоя вшита в bind-базу: если снимать базу до неё, анимация
каждый кадр возвращала бы модель в исходную A-позу.

### Производительность

Приложение сильно лагало на телефоне. Причина оказалась не в 3D-модели,
а в постоянной работе в кадре — вот что было исправлено:

| Что тормозило | Было | Стало |
|---|---|---|
| Фон `Ambient` | 3 слоя `filter: blur(70–90px)` с бесконечной анимацией, **на каждом экране** | статичные CSS-градиенты: 0 анимации, 0 filter |
| Нижняя навигация | `backdrop-blur-2xl` → переблюр фона **на каждый кадр скролла** | непрозрачный фон |
| Свайп карточки | анимируемый `boxShadow` с размытием 60px — тень не композитится, каждый кадр перерисовка | два слоя, у которых меняется только `opacity` (GPU) |
| Календарь | 42 `motion.button` (по одному на ячейку) | обычные кнопки + `active:scale` |
| Обновление статов | пересборка скелета + перебиндивание скиннинга, **14.2 мс** на каждое изменение XP | `restyleAvatar()` — **0.25 мс**, в 57× быстрее |
| 3D в кадре | 60 fps всегда, во всех инстансах | 30 fps, пауза при скролле и вне вьюпорта, `still` для мелких |
| three.js | попадал в общий бандл через `Ambient` → грузился даже на календаре | отдельный чанк 612 КБ, только там, где есть аватар |

Ключевые приёмы в коде:

- `lib/statVisuals.ts` — цвета и нормализация статов вынесены из
  `avatar3d.ts`, чтобы `Ambient` (он в корневом layout) не тянул three
- `components/AvatarLazy.tsx` — `dynamic(..., { ssr: false })`,
  страница рисуется сразу, персонаж догружается следом
- CSS `contain` на карточках и слотах канваса — перерисовка одной
  карточки не пересчитывает лэйаут соседей
- при паузе (скролл / вне экрана) часы анимации продолжают идти,
  иначе после возобновления копится дельта и персонаж дёргается

### Загрузка

Модель парсится один раз и кэшируется, дальше клонируется вместе
со скелетом (обычный `clone()` ломает скиннинг). Путь вынесен
в `NEXT_PUBLIC_MODEL_ORIGIN` — можно отдать с CDN. Если скелет
не совпал по именам, загрузчик падает с явной ошибкой, а компонент
показывает запасной бейдж с уровнем — экран не ломается.
