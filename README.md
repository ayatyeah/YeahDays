# YeahGrind

Ежедневный план, учебные маршруты и прогресс персонажа. Основной сценарий:
**Сегодня → следующий шаг → выполнение → результат → продолжение или повторение.**

## Разделы

- `/` — лендинг; `/today` — задачи и следующий шаг; `/app` — колода и персонаж.
- `/calendar`, `/progress`, `/account` — расписание, результаты, профиль.
- `/learn` — предметы, маршруты, уроки и практика; `/events` и `/stories` — учебные форматы.
- `/community`, `/team`, `/challenge30`, `/chat` — совместная работа, челлендж и ИИ.
- `/rmt` — отдельный исследовательский режим с согласием и группами A/B.
- `/admin` — управление; вкладка аналитики содержит статусы фоновых заданий.

## Стек и устройство

Next.js 16 App Router, React 19, TypeScript, Prisma/PostgreSQL, Auth.js,
Zustand, Tailwind CSS, Framer Motion. PWA использует `public/sw.js`.

`src/app` содержит маршруты/API; `src/components` — интерфейс;
`src/sections` — основные разделы оболочки; `src/lib` — предметную логику;
`src/store` — клиентское состояние; `src/i18n` — переводы.

Основной прогресс синхронизируется по протоколу 2: подтверждённый снимок,
трёхстороннее объединение задач и серверная версия. Учёба и ивенты имеют
собственные API. Подробнее: [контракт синхронизации](docs/operations/sync.md).

## Безопасный локальный запуск

Нужны Node.js 22.13+ или 24 (см. `.nvmrc`) и локальная PostgreSQL. `.env` не должен содержать адрес
боевой базы при разработке и тестировании.

```bash
npm ci
cp .env.example .env.local
# Укажи DATABASE_URL отдельной локальной базы и AUTH_SECRET в .env.local.
# Prisma CLI не читает .env.local: передай тот же локальный URL явно.
DATABASE_URL='postgresql://localhost/yeahgrind_dev' npm run db:deploy
npm run dev
```

Параметры подключений описаны в `.env.example` и [LMS.md](docs/LMS.md).
Не копируй реальные токены в отчёты, fixtures или репозиторий.

## Проверки и выпуск

```bash
npm run lint
npm run typecheck
npm test
npm run build
# Или все четыре последовательно:
npm run check
```

Сборка проверяет типы. Workflow `Quality` запускает проверки и миграции
на временной PostgreSQL, затем репетирует backup/restore с синтетическими
данными. Для обязательного статуса перед merge настрой защиту `main`:
required check `quality`. Настройки GitHub/Railway не изменяются файлами CI
автоматически. В `railway.json` задан build command `npm run check`;
применение миграций — отдельный шаг перед запуском новой версии.

## Переводы

Новые интерфейсные строки добавляются в `src/i18n/messages.ts` сразу для
RU/EN/KK и вызываются через `useT()`. Навигация, следующий шаг и экран
занятия используют этот подход; их контейнеры помечены `data-no-i18n`.
Пользовательские тексты и содержимое курсов не переводятся по UI-ключам.
`DomTranslator` пока обслуживает старые экраны: переносить их следует
по компонентам, не отключая переводы сразу во всём приложении.

## Материалы проекта

- `prisma/migrations` — единственная последовательность новых миграций.
- `docs/sql` — исторические SQL-изменения; повторно поверх baseline не запускать.
- `docs/operations` — эксплуатация и выпуск.
- `docs/diploma`, [docs/diploma-en](docs/diploma-en/README.md) — диплом.
- `docs/archive` — исторические описания, не инструкции для текущего выпуска.
- `artifacts/` — локальные результаты проверок, исключены из Git.

Ранее созданные личные PDF/DOCX/ZIP в корне остаются на своих местах.
Новые учебные исходники хранить под `docs/coursework/<course>/`, готовые
экспортируемые файлы — в `artifacts/exports/`. Секреты и резервные копии БД
в Git не добавлять.

## Сохранение, языки и диагностика

В приложении виден статус сохранения: локальные изменения ожидают отправки,
синхронизируются, сохранены либо остались на устройстве без сети. Ошибка записи
учёбы/настроек показана отдельно; повтор выполняется человеком, чтобы не
дублировать действие. Ошибка localStorage не маскируется статусом «Сохранено».

Основные сценарии входа, Today, учёбы и настроек используют React-переводы
`useCopy` / `useT`; английский и казахский словари загружаются по необходимости.
`coreCoverage.test.ts` проверяет покрытие перенесённых сообщений. DOM-перевод
сохранён для остальных старых разделов, но отключён на основных маршрутах.
Переводы интерфейса не меняют личные названия задач и содержание учебных материалов.

`RuntimeSignal` содержит только часовые счётчики: версия сборки, шаблон пути,
категория ошибки, HTTP-статус, диапазон длительности. Нет текста ошибок,
stack trace, URL-параметров, userId, email, содержимого задач и снимков экрана.
IP используется лишь для временного ограничителя запросов в RAM. Сервер
повторно фильтрует поля, ограничивает объём и частоту; записи старше 30 дней
очищаются при следующей записи, максимум раз в час. `/api/owner/diagnostics`
доступен только владельцу и показывает последние 24 часа в консоли аналитики.
Длительность клиентского API включает сеть и ожидание заголовков ответа;
это не отдельный замер времени SQL или серверной функции.

## Воспроизводимые замеры

`scripts/mobile-performance.mjs` запускается с `E2E_BASE`, `E2E_DB`,
`DATABASE_URL`, `PGHOST` и `PGUSER` отдельной локальной тестовой базы.
Измеряет три холодных открытия `/login` и `/today`: Chromium, 390×844,
150 мс задержки сети, 1.6 Мбит/с download, CPU ×4, service worker отключён.
`PERF_OUTPUT` задаёт путь JSON. Это лабораторная эмуляция, не замер реального
телефона в сотовой сети. Готовность означает появление формы/следующего шага,
а LCP и объём передачи фиксируются отдельно.

`scripts/memory-soak.mjs` требует явный DATABASE_URL локальной базы с `test`
в имени, уже применённые миграции и production build. Создаёт четыре временных
аккаунта по 500 задач и отдельный сервер на порту 3131; в течение часа выполняет
GET state/Today и каждые пять минут четыре одновременные загрузки JPEG 4000×3000.
Удаляет только собственные фото и аккаунты. Артефакты с RSS каждые 250 мс,
логом и итогом пишет в отдельный временный каталог. Запускать без параллельной
пересборки этого же каталога; для сравнения использовать отдельную копию build.
