# ДиДи

Голосовой помощник на OpenAI: просыпается на слово «Джарвис», говорит «Всегда
к вашим услугам», управляет задачами и настроением в YeahGrind, может
открывать программы/сайты, работать с файлами и запускать команды на
ноутбуке. Отдельное desktop-приложение на Electron со своим окном — не
веб-страница (браузер физически не может делать половину из перечисленного) —
и не консольный скрипт, как раньше: устанавливается через обычный
Windows-инсталлятор и работает как единый процесс с GUI, а не CLI без окна.

Работает независимо от YeahGrind-веба, но обязательно вместе с ним: обе
части общаются через одну и ту же Railway Postgres (задачи, настроение,
переписка, долговременная память) — desktop-приложение читает и пишет туда
же, куда пишет браузер.

**Проверено живым запуском собранного .exe** (не только typecheck) — весь
путь микрофон → распознавание слова → запись команды → GPT → голос ответа
работает и внутри упакованного Electron-приложения, включая нативный
модуль микрофона после `@electron/rebuild`.

## Как устроено распознавание «Джарвис»

**Два режима, выбираются автоматически при каждом запуске голосового цикла.**

**Локально (по умолчанию, если доступно) — openWakeWord.** Отдельный
Python-подпроцесс (`wakeword/detect.py`) держит загруженной готовую
модель `hey_jarvis` (ONNX) и получает от Electron КАЖДЫЙ кадр с
микрофона напрямую, в обход всего остального кода. Пока модель не увидела
кодовое слово — вообще ничего не уходит по сети, ни в OpenAI, ни куда-либо
ещё. Как только сработало — уходит в Node только то, что сказано ПОСЛЕ
этого момента (сама команда), она и едет в Whisper. Плата за это:
модель — предобученная под английское произношение "jarvis", а не
кириллическое "джарвис" — распознаёт увереннее что-то среднее между
русским и английским звучанием слова, чем чистое русское "джжарвис". И
ещё одна плата: «одним дыханием» («Джарвис, добавь молоко» без паузы)
больше не работает — детектор ловит только сам факт слова, не текст
следом, поэтому команда всегда произносится отдельным, вторым заходом
после короткой паузы — как у обычных умных колонок.

**Через Whisper (запасной путь) — если Python/openwakeword не найдены.**
Старое поведение: ДиДи постоянно слушает, дожидается конца фразы и
прогоняет её через Whisper целиком; если в тексте нашлось слово, близкое к
«джарвис»/«жарвис»/«jarvis» (нечёткое сравнение — Whisper не всегда
расслышит точь-в-точь) — это она. У этого пути обратная сторона: **буквально
всё, что скажешь рядом с микрофоном (включая случайный разговор с самим
собой), уходит в OpenAI на транскрипцию**, просто без побочного эффекта в
виде ответа/действия — модель тут не сравнивает, слово оно или нет, до
того, как всё уже отправлено и распознано. Ещё у Whisper на слабом/
неоднозначном звуке (тишина, дыхание, шум) бывают галлюцинации — правдо­
подобный, но случайный текст, часто вообще на другом языке (кириллица/
латиница фильтруется отдельно, `openai.ts::transcribeWav`, но не спасает,
если галлюцинация сама вышла латиницей/кириллицей). Плюс этого пути —
можно сказать «одним дыханием», без паузы после кодового слова.

### Как поставить локальный детектор

```powershell
py -m pip install -r wakeword/requirements.txt
```

Требует Python 3 на машине (`python`/`py` в PATH) — отдельный шаг, не
часть установки самого DiDi.exe: инсталлятор Python не тянет и не
устанавливает сам. Без этого приложение не сломается — просто перейдёт на
запасной путь через Whisper (см. выше) и напишет об этом в живом журнале
на вкладке «Статус» при каждом запуске.

**Памяти между репликами нет — каждая команда требует свежего «Джарвис».**
Раньше был режим, в котором ДиДи ещё несколько минут после ответа держала
контекст и не требовала повторного кодового слова — убрали: на практике
это значило, что любой посторонний разговор в комнате в этом окне мог
восприняться как обращение к ней.

**Приветствие при старте.** Один раз при запуске голосового цикла (автозапуск
при входе в Windows или открытие приложения вручную) ДиДи сама, без кодового
слова, говорит `BOOT_GREETING` (`systemPrompt.ts`) — «С возвращением,
сэр. Чем могу вам помочь?». Не путать с `GREETING` — та фраза звучит на
каждое «Джарвис», а эта — только один раз при старте.

**Ответ озвучивается по предложениям, а не весь целиком после того, как
модель допечатает.** Чат-ответ идёт потоково (`stream: true`); как только
накопленный текст складывается в законченное предложение, синтез речи для
него запускается сразу, в фоне, пока модель продолжает генерировать
остальной ответ (`voice.ts::startStreamingSpeech`) — заметно короче пауза
до первого звука на длинных ответах. Микрофон при этом глушится один раз
на весь ответ, а не между каждым предложением.

## Прежде чем запускать — что нельзя сделать за тебя

1. **OpenAI API-ключ** и остальные обязательные поля — заполняются во
   вкладке **«Настройки»** внутри самого приложения при первом запуске
   (не нужно руками редактировать файлы), либо через `assistant/.env` в
   dev-режиме (см. ниже).
2. **Свой userId в YeahGrind.** Открой приложение в браузере → DevTools →
   Console → `localStorage.getItem("yd-uid")`. Это `YEAHGRIND_USER_ID`.

Больше ничего внешнего не нужно — ни Picovoice, ни Python, ни отдельных
аккаунтов для детекции слова.

## Установка (для пользователя — просто .exe)

```powershell
cd assistant
npm install
npm run dist
```

Соберёт `assistant/release/DiDi Setup <версия>.exe` — обычный
Windows-инсталлятор (NSIS): даёт выбрать папку установки, кладёт ярлык на
рабочий стол. Установщик не подписан сертификатом — при первом запуске
Windows SmartScreen покажет предупреждение «Неизвестный издатель», это
ожидаемо для локально собранного .exe, жми «Всё равно выполнить».

При первом запуске приложение откроется с пустыми настройками — заполни
вкладку **«Настройки»** (OpenAI-ключ, адрес YeahGrind, userId, тот же
`ASSISTANT_SECRET`, что и в корневом `.env` YeahGrind) и нажми «Сохранить
и перезапустить». Хранится это не рядом с .exe (Program Files обычно
недоступен для записи обычному пользователю), а в
`%APPDATA%\didi-assistant\.env`.

В корне репозитория YeahGrind (`../`) в `.env` должен быть тот же секрет:

```
ASSISTANT_SECRET=<любая длинная случайная строка>
```

Без него `/api/assistant/*` отвечает 401 — осознанно, эти эндпоинты дают
доступ к задачам, настроению и памяти аккаунта. То же значение должно быть
и в Railway → Variables на проде, если используешь его (см. ниже).

**Адрес YeahGrind: localhost или прод?** Если хочешь, чтобы ДиДи работала
сразу после входа в Windows без поднятого рядом `npm run dev` — укажи прод
(например `https://твой-проект.up.railway.app`). База данных одна и та же
в обоих случаях (Railway Postgres) — разница только в том, какое запущенное
приложение обслуживает `/api/assistant/*`.

Если логинишься через Google на выбранном адресе — `YEAHGRIND_USER_ID`
после этого сменится (был анонимный device-id, станет id аккаунта), нужно
обновить во вкладке «Настройки», иначе ДиДи продолжит работать со старым,
уже неактуальным профилем.

Если микрофон определился не тот — `npm run devices` (из исходников, не
из установленного .exe) покажет список, нужный индекс — в поле
`AUDIO_DEVICE_INDEX` в «Настройках».

### Разработка (без сборки инсталлятора)

```bash
cd assistant
cp .env.example .env    # заполнить все поля — в dev читается этот файл, а не userData
npm install
npm run dev
```

`npm run dev` поднимает Electron-окно с hot-reload интерфейса. Приложение
YeahGrind должно быть поднято отдельно (`npm run dev` в корне репозитория,
или прод) — ДиДи ходит в его API.

## Использование

Окно ДиДи — четыре вкладки: **Статус** (онлайн/офлайн, вкл/пауза, кнопка
запуска/остановки голосового цикла, живой журнал того, что она слышит и
делает), **Чат** (та же переписка, что на странице `/didi` в YeahGrind —
голос и текст в одной ленте), **Факты** (долговременная память, см. ниже —
можно посмотреть, добавить и удалить руками) и **Настройки**.

Закрытие окна крестиком сворачивает приложение, а не выключает голосовой
цикл — он продолжает слушать в фоне, как раньше вёл себя CLI без окна
вообще. Полностью выйти — кнопка «Выйти из ДиДи полностью» во вкладке
«Настройки».

Скажи «Джарвис» (в любом месте фразы) — услышишь «Всегда к вашим услугам»,
затем говори команду. Или сразу: «Джарвис, ...».

Если после голого «Джарвис» ничего не сказать — через
`WAKE_COMMAND_TIMEOUT_SECONDS` (по умолчанию 3с) ДиДи молча возвращается
к фоновому прослушиванию, а не ждёт команду бесконечно.

**«Джарвис, стоп»** (или просто «стоп»/«хватит»/«отставить» в разговоре)
— обрывает текущий диалог и отвечает «Остановился, сэр», **без единого
обращения к GPT** — как и остальные "быстрые команды" (`quickCommands.ts`).
Не путать с прерыванием ответа НА ЛЕТУ: пока ДиДи говорит, микрофон
выключен (см. voice.ts — чтобы не слышать себя же), так что перебить её
голосом посреди фразы физически нельзя — "стоп" сработает только между
репликами, как обычная команда.

**«Джарвис, запомни ...»** — тоже без GPT: всё, что сказано после
«запомни» (или «запомни про меня, что ...»), уходит как есть в БД
(`AssistantFact`, таблица отдельная от переписки и от истории разговора).
Это долговременная память о пользователе, а не контекст одного диалога —
переживает и «стоп», и перезапуск процесса. Читается заново в начале
КАЖДОГО нового разговора (`conversation.ts::freshHistory`) и подмешивается
в системный контекст — значит, факт, добавленный посреди сессии текстового
чата, увидит только следующий разговор, не текущий. Никакого разбора или
дедупликации контента — что сказал, то и легло; если попросишь запомнить
одно и то же дважды, будет два факта.

Ещё пара мелких команд без GPT: «который час»/«сколько времени» (текущее
время с ноутбука) и «спасибо»/«благодарю» (короткий ответ без похода к
модели).

### Автозапуск при входе в Windows

Тоггл «Запускать при входе в Windows» во вкладке «Настройки» — через
встроенный Electron API (`app.setLoginItemSettings`), без Task Scheduler и
VBS-скриптов, которыми это делалось в CLI-версии (тот подход убран вместе с
`npm start`: `scripts/autostart.ps1` и `start-hidden.vbs` удалены — если у
тебя ещё стоит старая задача в Task Scheduler на `npm start`, она сломается,
потому что такого скрипта в package.json больше нет; включи автозапуск
заново через новый тоггл).

## Что ДиДи умеет

- **Задачи и настроение YeahGrind**: прочитать план на сегодня, добавить
  задачу, отметить выполненной, записать настроение/энергию.
- **Открыть** программу, файл, сайт.
- **Файлы**: показать содержимое папки, прочитать текстовый файл,
  записать/переместить/удалить файл.
- **Команды**: выполнить произвольную команду PowerShell и услышать вывод.
- **Медиа**: пауза/следующий/предыдущий трек, звук — через системные
  медиаклавиши (не абсолютная громкость в процентах — для этого нужна
  сторонняя утилита вроде nircmd, её здесь нет).

## Подтверждение перед необратимым — отключено

По явному запросу пользователя запись файла, перемещение, удаление и
выполнение произвольной команды выполняются **сразу**, без «да/нет»
(`src/main/didi/tools.ts`, `destructive: false` для всех четырёх). Раньше
это подтверждение было обязательным барьером — теперь его нет: если STT
что-то не так расслышит, действие всё равно выполнится. Осознанный
компромисс в пользу скорости, а не техническое ограничение — обратно
включить одной строкой (`destructive: true` в `tools.ts`) в любой момент.

Удаление файла по-прежнему уходит в корзину, не насовсем — это не связано
с подтверждением и осталось как есть.

Каждая такая команда и файловая операция всё равно пишется в
`assistant/didi-actions.log` с меткой времени, а инструкция беречься от
подозрительных команд, найденных не в живой речи (например, в тексте
файла или веб-страницы), в системном промпте осталась — модель должна
переспросить в этом случае, хоть это и не техническая гарантия.

## Панель в профиле YeahGrind

В разделе «Профиль» веб-приложения тоже есть статус ДиДи (слушает/на паузе/
офлайн), тоггл вкл/выкл и лента последних действий — это то же самое
состояние, что и вкладка «Статус» в desktop-приложении, просто ещё один
способ посмотреть, не открывая ДиДи отдельно. ДиДи стучится туда раз в
~15с; desktop-окно и веб-страница не соединяются друг с другом напрямую —
оба говорят с одним и тем же Next-сервером YeahGrind (`src/main/didi/bridge.ts`
на стороне приложения), чтобы не упереться в CORS/mixed-content между
HTTPS-страницей и локальным процессом.

## Известные ограничения — честно

- **Инсталлятор не подписан.** Нет сертификата code signing — Windows
  SmartScreen будет предупреждать при первом запуске `.exe`. Косметика,
  не влияет на работу, но выглядит тревожно для незнакомого с этим
  человека.
- **Иконка приложения — стандартная Electron**, не своя. Не критично, но
  выглядит "недоделанным" в панели задач — если появится готовый логотип,
  положить `.ico` в `assistant/build/icon.ico` и прописать в
  `electron-builder.yml` (`win.icon`).
- **Настройки применяются только после перезапуска** — вкладка «Настройки»
  пишет `.env` на диск, но `dotenv` читает его один раз при старте
  процесса (`didi/config.ts`), поэтому после сохранения нужна кнопка
  «Сохранить и перезапустить», а не мгновенное применение.
- **Автозапуск неизбежно тянет за собой ~85 МБ Electron-рантайма** в
  памяти на всё время работы, в отличие от лёгкого Node.js CLI-процесса,
  который был раньше — цена за окно и GUI.
- **Гонка с открытой вкладкой браузера**: YeahGrind хранит состояние как
  один JSON-блоб на пользователя с last-write-wins по времени изменения.
  Если вкладка открыта и в ней есть несинхронизированные локальные правки,
  которые сохранятся ПОСЛЕ правки от ДиДи, они её перезапишут. Для одного
  пользователя без параллельной работы в браузере в момент голосовой
  команды это не проблема, но это не honest-to-god многопользовательская
  синхронизация.
- **`run_command`** — это выполнение произвольного кода с правами твоего
  пользователя Windows. Голосовое подтверждение — единственный барьер.
  Модель также проинструктирована переспрашивать, если "команда"
  обнаружена внутри текста файла/страницы, а не сказана вслух (защита от
  prompt injection), но это инструкция в промпте, а не техническое
  ограничение — не полагайся на неё как на гарантию.
- **Ложные срабатывания детекции**: и у локального openWakeWord, и у
  запасного Whisper-пути сравнение нечёткое, так что похожее слово в
  обычном разговоре теоретически может отреагировать. Реже, чем с
  коротким словом вроде «yeah», но не исключено полностью.
- **Локальный детектор не тюнился под конкретный голос/помещение** —
  порог срабатывания (`THRESHOLD = 0.5` в `wakeword/detect.py`) взят из
  документации openWakeWord как разумное значение по умолчанию, не
  проверялся вживую на реальном произношении "Джарвис" с русским акцентом.
  Если совсем не реагирует или наоборот слишком дёргается — первое, что
  стоит покрутить.
- **Python-подпроцесс — точка отказа без авто-восстановления**: если он
  упадёт посреди работы (не при старте — тогда просто откатится на
  Whisper-путь), голосовой цикл целиком останавливается с ошибкой в
  журнале, а не переключается на запасной путь на лету — нужно нажать
  «Запустить голос» заново на вкладке «Статус».
- **Порог тишины калибруется автоматически** при каждом запуске (первая
  секунда — замер фонового шума комнаты, порог ставится с запасом над
  ним, см. `calibrateSilenceThreshold()` в `audio.ts`) — так он не "уезжает",
  если потом поменяешь громкость микрофона в Windows. Обрывки короче 0.5с
  в Whisper не отправляются вообще (`MIN_UTTERANCE_SAMPLES`) — раньше
  именно они улетали в API и Whisper отвечал "audio corrupted or
  unsupported", из-за чего казалось, что ДиДи "плохо понимает слово".
  Если всё ещё обрезает фразы или подолгу ждёт после конца речи — крути
  `SILENCE_FRAMES_TO_STOP`/`SPEECH_START_FRAMES` в `audio.ts`.
