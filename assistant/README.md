# ДиДи

Голосовой помощник на OpenAI: просыпается на слово «Джарвис», говорит «Всегда
к вашим услугам», управляет задачами и настроением в YeahGrind, может
открывать программы/сайты, работать с файлами и запускать команды на
ноутбуке. Отдельное Node.js-приложение — фоновый процесс, не веб-страница
(браузер физически не может делать половину из перечисленного).

**Проверено живым голосом** (не только typecheck) — весь путь микрофон →
распознавание слова → запись команды → GPT → голос ответа реально работает.

## Как устроено распознавание «Джарвис»

Не через классификатор-детектор (как Porcupine/openWakeWord), а через
обычное распознавание речи: ДиДи постоянно слушает, дожидается конца
фразы (пауза = конец) и прогоняет её через Whisper. Если в тексте
встретилось слово, близкое к «джарвис»/«жарвис» (нечёткое сравнение —
Whisper не всегда расслышит точь-в-точь), — это она. Причина: ни
Picovoice/Porcupine (9 языков,
русского нет), ни openWakeWord (в принципе только английский, синтетика
для обучения англоязычная) не умеют нормально обучаться на русских словах.
STT-путь дороже по API и с задержкой ~1-2с вместо мгновенного отклика
классификатора, зато понимает настоящее русское произношение, а не
английскую транслитерацию.

Можно сказать и в одно дыхание — «Джарвис, добавь задачу купить молоко» —
тогда ДиДи не здоровается, а сразу выполняет; если сказать только «Джарвис» —
ответит «Всегда к вашим услугам» и отдельно дослушает команду.

## Прежде чем запускать — что нельзя сделать за тебя

1. **OpenAI API-ключ.** `OPENAI_API_KEY` в `assistant/.env` (не в
   корневом `.env` YeahGrind — это разные файлы для разных процессов).
2. **Свой userId в YeahGrind.** Открой приложение в браузере → DevTools →
   Console → `localStorage.getItem("yd-uid")`. Это `YEAHGRIND_USER_ID`.

Больше ничего внешнего не нужно — ни Picovoice, ни Python, ни отдельных
аккаунтов для детекции слова.

## Установка

```bash
cd assistant
cp .env.example .env    # заполнить все поля
npm install
```

В корне репозитория YeahGrind (`../`) добавь в `.env`:

```
ASSISTANT_SECRET=<любая длинная случайная строка>
```

Значение должно совпадать с `ASSISTANT_SECRET` здесь, в `assistant/.env`.
Без него `/api/assistant` отвечает 401 — это осознанно, эндпоинт даёт
доступ к задачам и настроению аккаунта.

Если микрофон определился не тот — `npm run devices` покажет список,
нужный индекс пиши в `AUDIO_DEVICE_INDEX`.

## Запуск

Приложение YeahGrind должно быть поднято (`npm run dev` или прод) — ДиДи
ходит в его API. Затем:

```bash
npm start
```

Скажи «Джарвис» (в любом месте фразы) — услышишь «Всегда к вашим услугам»,
затем говори команду. Или сразу: «Джарвис, ...».

## Что ДиДи умеет

- **Задачи и настроение YeahGrind**: прочитать план на сегодня, добавить
  задачу, отметить выполненной, записать настроение/энергию.
- **Открыть** программу, файл, сайт.
- **Файлы**: показать содержимое папки, прочитать текстовый файл,
  записать/переместить/удалить файл.
- **Команды**: выполнить произвольную команду PowerShell и услышать вывод.
- **Медиа**: пауза/следующий/предыдущий трек, звук — через системные
  медиаклавиши (не абсолютная громкость в процентах — для этого нужна
  сторонняя утилита вроде nircmd, её здесь нет).

## Подтверждение перед необратимым

Запись файла, перемещение, удаление и выполнение произвольной команды —
всегда через голосовое подтверждение («Точно сделать X? Скажи да или
нет»), это зашито в коде (`tools.ts`, `destructive: true`), а не в
системном промпте — модель не может это выключить формулировкой запроса.
Удаление файла уходит в корзину, не насовсем.

Каждая такая команда и файловая операция пишется в
`assistant/didi-actions.log` с меткой времени — если что-то пошло не так,
там видно, что именно и когда.

## Панель в профиле YeahGrind

В разделе «Профиль» веб-приложения есть статус ДиДи (слушает/на паузе/
офлайн), тоггл вкл/выкл и лента последних действий. ДиДи стучится туда
раз в ~15с; браузер и процесс ДиДи не соединяются друг с другом напрямую
(ни WebSocket, ни localhost) — оба говорят с одним и тем же Next-сервером,
чтобы не упереться в mixed-content между HTTPS-страницей и локальным
процессом.

## Известные ограничения — честно

- **Разговор без памяти между пробуждениями** — каждое «Джарвис» начинает
  новый контекст. Долгую беседу в несколько реплик ДиДи не ведёт.
- **Гонка с открытой вкладкой браузера**: YeahGrind хранит состояние как
  один JSON-блоб на пользователя с last-write-wins по времени изменения.
  Если вкладка открыта и в ней есть несинхронизированные локальные правки,
  которые сохранятся ПОСЛЕ правки от ДиДи, они её перезапишут. Для одного
  пользователя без параллельной работы в браузере в момент голосовой
  команды это не проблема, но это не honest-to-god многопользовательская
  синхронизация.
- **`run_command`** — это выполнение произвольного кода с правами твоего
  пользователя Windows. Голосовое подтверждение — единственный барьер.
  Модель также проинструктирована переспрашивать, если "команда"
  обнаружена внутри текста файла/страницы, а не сказана вслух (защита от
  prompt injection), но это инструкция в промпте, а не техническое
  ограничение — не полагайся на неё как на гарантию.
- **Ложные срабатывания STT-детекции**: сравнение нечёткое (допуск в 2
  правки от «джарвис»/«жарвис»), так что похожее слово в обычном разговоре
  теоретически может отреагировать. Реже, чем с коротким словом вроде
  «yeah», но не исключено полностью.
- **Порог тишины калибруется автоматически** при каждом запуске (первая
  секунда — замер фонового шума комнаты, порог ставится с запасом над
  ним, см. `calibrateSilenceThreshold()` в `audio.ts`) — так он не "уезжает",
  если потом поменяешь громкость микрофона в Windows. Обрывки короче 0.5с
  в Whisper не отправляются вообще (`MIN_UTTERANCE_SAMPLES`) — раньше
  именно они улетали в API и Whisper отвечал "audio corrupted or
  unsupported", из-за чего казалось, что ДиДи "плохо понимает слово".
  Если всё ещё обрезает фразы или подолгу ждёт после конца речи — крути
  `SILENCE_FRAMES_TO_STOP`/`SPEECH_START_FRAMES` в `audio.ts`.
