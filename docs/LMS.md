# Вход и личные дедлайны LMS AITU

На `/login` и `/register` есть переход «Войти / зарегистрироваться через LMS
AITU» (`/login/lms`). Логин и пароль проверяются через штатную форму AITU
с cookies и CSRF-токеном. После проверки входа и доступа к странице профиля
аккаунт YeahGrind определяется по Moodle user ID, а не по введённому логину
или совпадению email. Повторный вход возвращает в тот же профиль.
Пароль и cookies LMS не сохраняются. MFA, обязательная смена пароля и другие
незавершённые шаги не считаются успешным входом. Вход через внешнего провайдера
OpenID Connect этой формой не поддерживается.

Если аккаунт YeahGrind уже есть, сначала войти в него, затем открыть
**Настройки → Интеграции → LMS AITU → Подключить через логин LMS**. Это
сохраняет существующий прогресс. Другая уже привязанная LMS identity или
identity другого пользователя не может заменить текущую привязку.
Автоматического объединения по email нет.

После входа запрашивается постоянная ссылка экспорта календаря Moodle для
текущего пользователя. Она шифруется AES-256-GCM и хранится отдельно от
клиентского состояния, в `LmsConnection`. API статуса не отдаёт ссылку.
Если экспорт отключён/недоступен, вход всё равно работает; интерфейс явно
покажет, что дедлайны пока не загружены. Подключение можно повторить.

Первый импорт вызывается после входа. Далее существующий GitHub workflow
`lms-sync.yml` обновляет подключения три раза в день; ручная кнопка есть в
настройках. Каждый импорт пишет только в состояние владельца подключения.
Сбой одного календаря не останавливает остальные. Синхронизация сохраняет
существующие задачи и отметки выполнения, добавляет отсутствующие события.
Повторный импорт не дублирует одинаковые заголовок+дату. Как и раньше,
перенос дедлайна преподавателем создаёт новую задачу; старую надо убрать
вручную. Источник — события календаря, оценки и полное расписание занятий
через эту интеграцию не загружаются.

«Отключить календарь» удаляет сохранённый секрет и прекращает автообновление,
сохраняет импортированные задачи и способ входа. Следующий вход через LMS
снова подключит календарь. Удаление аккаунта удаляет подключение каскадом.

## Запуск на сервере

1. Перед запуском новой версии применить к нужной базе только добавление
   таблицы: `npx prisma db execute --schema prisma/schema.prisma --file docs/sql/2026-09-26-lms-connection.sql`.
   Для новой локальной базы можно использовать обычный `npm run db:push`.
2. `npm install` генерирует Prisma Client; при уже установленных зависимостях
   выполнить `npx prisma generate`.
3. Задать стабильный `LMS_ENCRYPTION_KEY` (случайный секрет, например результат
   `openssl rand -base64 32`). Если он не задан, используется `AUTH_SECRET`.
   Смена используемого ключа потребует повторного подключения календарей.
4. Собрать и запустить приложение; серверу нужен HTTPS-доступ к
   `lms.astanait.edu.kz`. Workflow использует прежний `CRON_SECRET`.
5. Проверить реальный вход, первый импорт, повторный вход и отдельный
   аккаунт второго студента. Успешный вход с реальной учётной записью
   в ходе разработки не проверен: выполнены проверки публичной формы,
   тесты с моделированием ответов LMS и проверки приложения.

Старые `LMS_ICAL_URL`, `LMS_SYNC_USER_ID`, `LMS_TIMEZONE` продолжают работать
для владельца до привязки его LMS identity. После привязки используются
персональные настройки; отключение календаря не включает старый env-синк.

`GET /api/account/lms` — статус, `POST` — синхронизация, `DELETE` — отключение.
Все три требуют сессию и выбирают владельца из неё. Переданный клиентом ID
не используется. `POST /api/cron/lms-sync?dry=1` возвращает сводку по каждому
подключению без записи состояния/статуса и без push.

## Основание интеграции

- [Форма входа AITU](https://lms.astanait.edu.kz/login/index.php).
- [Login token в Moodle](https://docs.moodle.org/dev/Login_token).
- [Генерация ссылки экспорта](https://github.com/moodle/moodle/blob/MOODLE_405_STABLE/calendar/export.php).

HTML-интеграция зависит от формы Moodle: изменение разметки или политики
входа университетом может потребовать обновления клиента.
