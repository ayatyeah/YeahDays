# Фоновые задания

LMS, dispatch и digest записывают время запуска, последнего успеха/ошибки и
число последовательных ошибок в BackgroundJob. Данные сохраняются после
перезапуска. Три ошибки подряд дают структурированную запись
`background_job_repeated_failure` в серверном логе и предупреждение в
`/admin` → аналитика. API статусов доступен только администратору.

HTTP-ошибка, частичный сбой LMS и неуспешная отправка push не маскируются
успехом. Cron использует curl --fail с ограничением времени; GitHub помечает
такой запуск как failed. Подписка на уведомления GitHub о failed workflows
настраивается владельцем аккаунта отдельно.

Нет последнего запуска или превышен ожидаемый интервал — панель показывает
это отдельно от успешной работы. При отключённых VAPID/планировщике отсутствие
успеха ожидаемо; панель не выдумывает успешную отправку.

Внешние email/Slack/webhook оповещения не настроены. Для них требуется
выбранный получатель/канал. В текущем изменении сигнал — статус CI,
администраторская панель и структурированный серверный лог.
