# Ежедневная резервная копия

Workflow `Production backup and restore` запускается ежедневно в 22:17 UTC
(03:17 Asia/Almaty) и вручную через GitHub Actions. Хранение — 14 дней.
Репозиторий публичный: в artifacts попадает только GPG AES-256 архив,
его SHA-256 и итог проверки. Незашифрованный dump удаляется с временного runner.

Источник читает отдельная роль PostgreSQL `yg_backup_20261101`:
`pg_read_all_data`, `default_transaction_read_only=on`, максимум два соединения.
GitHub secrets: `BACKUP_DATABASE_URL`, `BACKUP_PASSPHRASE`. Не выводить их в логи.
Локальный аварийный экземпляр ключа находится у владельца в защищённом файле
`~/.local/share/yeahgrind/backups/automation/credentials.json` (права 0600).
Его нужно хранить отдельно от зашифрованных архивов. Без ключа восстановить
содержимое GPG-архива нельзя. Смена ключа не расшифрует старые копии.

Каждый запуск не только делает dump: он расшифровывает результат, сравнивает
байты с оригиналом, полностью восстанавливает его в отдельный PostgreSQL 18,
проверяет наличие основных таблиц, связи пользователей со снимками и увеличение
ревизии при записи. Тестовая запись откатывается транзакцией. Тестовая база
удаляется. Production не является целью восстановления ни в одном шаге.

Проверка выполнена также локально на реальной копии 1 ноября 2026.
Первый автоматизированный полный цикл успешно выполнен в GitHub Actions:
[run 41289816429](https://github.com/ayatyeah/YeahDays/actions/runs/41289816429).
Ошибки любого этапа делают workflow красным; обычные уведомления GitHub Actions
зависят от настроек уведомлений владельца репозитория.

Восстановление вручную: скачать artifact, проверить SHA-256, расшифровать GPG
с сохранённым ключом в защищённый каталог и выполнить `pg_restore --exit-on-error
--no-owner --no-acl` на НОВОЙ отдельной базе. Сначала проверить приложение на
восстановленной базе; не заменять рабочую базу без отдельного решения оператора.
