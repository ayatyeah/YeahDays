# Память приложения

Production запускается через `railway.json`: Node с `--optimize-for-size`,
кучей V8 до 256 МиБ, young-generation semi-space 2 МиБ и `MALLOC_ARENA_MAX=2`.
256 МиБ — предел old-generation V8, а не всего RSS контейнера: нативные
библиотеки, буферы, код и кэши расходуют память отдельно.

Ограничения приложения:

- Prisma singleton общий для route bundles и instrumentation, включая production.
  По умолчанию пул содержит максимум 5 соединений. Явный `connection_limit`
  в DATABASE_URL сохраняется и имеет приоритет.
- Кэш Next.js в RAM — 8 МиБ; дисковый кэш продолжает работать.
- Фоновые уведомления и очистка research читают по 25 записей. Курсор по ID
  не зависит от удаления предыдущей порции. Лимит dispatch 300 за прогон сохранён.
- Sharp для пользовательских фото и AI planner не сохраняет кэш операций,
  использует один поток libvips на изображение. Это не ограничивает весь RSS
  декодирования и не является глобальным лимитом параллельных загрузок.
- Ограничитель запросов хранит максимум 5000 ключей и не записывает отклонённые
  попытки. При заполнении отклоняет новые ключи до освобождения просроченных;
  действующие ограничения входа не вытесняются. Окно теперь отсчитывается от
  принятых попыток, повторный отклонённый запрос не продлевает блокировку.

## Проверка 1 ноября 2026

Синтетическая локальная нагрузка: production build, Node 24.19.0,
PostgreSQL, снимок из 1000 задач, 1000 HTTP-запросов (10 параллельно),
публичные страницы, auth/session, state; пауза 15 секунд после нагрузки.
Измеряется RSS именно процесса сервера, а не тестового клиента.

| Показатель | До | После |
| --- | ---: | ---: |
| Пиковый RSS, МиБ | 255.9 | 222.1 |
| RSS после нагрузки, МиБ | 232.0 | 215.9 |
| p95 ответа, мс | 30 | 34 |
| Ошибки HTTP | 0 | 0 |

Это короткий синтетический прогон, не прогноз расхода при любом трафике.
Изображения и рассылки в HTTP-нагрузку не входят; прохождение нескольких
порций уведомлений и очистки проверяется отдельными тестами.

Railway перед изменением: 310.1 МБ среднего / 311.5 МБ максимального
расхода за стабильное окно 07:53–08:00 UTC. Первый час с деплоями не следует
использовать как чистое сравнение. После выпуска сравнивать отдельное окно
нового deployment, включая разогрев и реальные запросы:

```sh
railway metrics -s YeahDays -e production --memory --cpu --since 1h --json
```

Источники настроек: [Next.js self-hosting](https://nextjs.org/docs/app/guides/self-hosting),
[Prisma v6 connection pool](https://www.prisma.io/docs/orm/v6/prisma-client/setup-and-configuration/databases-connections/connection-pool),
[Sharp performance](https://sharp.pixelplumbing.com/performance/),
[Sharp cache/concurrency](https://sharp.pixelplumbing.com/api-utility/).
Флаг V8 проверен через `node --v8-options` установленного Node.
