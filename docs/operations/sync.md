# Синхронизация состояния: protocol 2

Клиент хранит последний подтверждённый снимок и revision отдельно для каждого
аккаунта (`yg-sync-v2:<owner>`). PUT передаёт `{protocol:2, data, base,
baseRevision}`. GET возвращает `{data, revision}` или `unchanged` при совпадении
серверной версии. Ошибка базы — HTTP 503, никогда не пустой успешный снимок.

Сервер объединяет base/local/remote внутри транзакции с блокировкой строки.
Списки с id (задачи, подзадачи, цели, действия) объединяются по id; независимые
поля сохраняются. Удаление известной в base записи побеждает параллельную
правку: старое устройство не восстанавливает её. Изменения разных полей
объединяются, конфликт одного скалярного поля решается порядком сохранения
на сервере. Массивы строк объединяются с учётом удалений. Прочие массивы
считаются единым значением. Счётчики не суммируются автоматически.

При первом подключении без base сервер сохраняет свои значения при конфликте,
импортируя новые записи. Это консервативный переход со старого протокола:
невозможно восстановить историю офлайн-удалений, которой старый клиент не вёл.
Старый PUT получает 409 с просьбой обновить приложение. Обновляй клиент и API
вместе после миграции. Клиентские часы не определяют приоритет записей.

Revision увеличивает триггер PostgreSQL при любом UPDATE, включая старые
SQL-интеграции. Серверные интеграции `loadState/saveState` также используют
базовый снимок. Не добавляй новые read-modify-write операции через прямой
upsert: используй mergeUserState или транзакцию.

Клиент сериализует запросы, сохраняет изменения, сделанные во время запроса,
и отменяет старые запросы при смене аккаунта. Офлайн-данные остаются в Zustand
persist; повтор — при восстановлении сети, открытии вкладки или ручной
синхронизации. Перенос гостя подтверждается только успешным ответом `/api/link`.

Проверки: syncMerge.test.ts, linkAccount.test.ts, state/route.test.ts,
userState.db.test.ts, e2e/specs/06-sync.mjs. Проверки БД требуют явно указанной
локальной тестовой базы; unit-тесты не используют боевую базу из `.env`.
