# Проверка изменений — 1 ноября 2026

## Реализовано

1. Протокол синхронизации 2: подтверждённая база на устройстве, объединение
   по id и полям, удаление побеждает конкурентную правку, серверные версии,
   блокировки PostgreSQL, отмена старых запросов при смене аккаунта.
2. Перенос гостевого прогресса подтверждается только успешным HTTP-ответом;
   ошибки повторяются, чтение недоступной БД возвращает 503.
3. ESLint 10, `npm run check`, обязательный typecheck сборки, workflow Quality,
   проверка сборки в railway.json. Next обновлён в пределах 16.x до 16.4.3.
4. Вход, онбординг и запуск PWA ведут в Сегодня. Следующий шаг находится
   наверху; колода раскрывается отдельно и загружается по запросу.
   Календарь/колода подсвечивают Сегодня в обеих навигациях.
5. Занятие вынесено из LearningPage в LearningLesson; добавлены этапы,
   воспроизведение ответа, сравнение с разбором, повторение на завтра и
   отметка запланированного повторения без повторной награды за квест.
6. Сохранение статуса фоновых заданий, последнего успеха и серии ошибок;
   панель администратора, структурированные логи; cron больше не скрывает
   ошибки. Частичный сбой LMS и неуспешные push возвращают неуспех.
7. Baseline и следующая миграция, автоматическая репетиция dump/restore.
8. Типизированные ключи RU/EN/KK для навигации, следующего шага, занятия,
   повторения и статусов фоновых заданий. Остальные старые экраны пока
   используют DomTranslator, как предусмотрено поэтапной миграцией.
9. Актуальный README, инструкции эксплуатации, исторический README в архиве.
   Существующие личные материалы и исходные пользовательские правки сохранены.

## Фактически выполнено

- `npm run check`: lint, TypeScript, 823 unit-теста и production build прошли.
  Пропущено 6 тестов: 3 новых PostgreSQL-теста включаются отдельно, ещё 3
  требуют внешних/специальных условий. Пропуски не названы успешными тестами.
- `SYNC_DB_TEST=1 ... vitest run src/lib/userState.db.test.ts`: 3/3 на отдельной
  локальной PostgreSQL — конкурентные изменения, удаление/повтор запроса,
  увеличение версии при прямой SQL-записи.
- `db:restore-check`: чистая установка двух миграций, синтетическая запись,
  pg_dump/pg_restore, совпадение отпечатков данных и работа триггера после
  восстановления. Временные базы и dump удалены.
- Chromium, production build: `Качество` — 2 сценария / 9 проверок;
  `Главная: свайп` — 1 сценарий / 10 проверок. Проверены реальные offline
  browser contexts, сохранение задач после перезагрузки, отсутствие цикла
  перезаписей, навигация EN/KK, повторение, свайпы и завершение действия.
- Chromium, dev build в ходе работы: `Синхронизация` — 2 сценария / 8 проверок;
  `Учёба: обзор` — 1 сценарий / 18 проверок (генерация и оценка имитируются
  тестовой fixture; реальный AI-провайдер не вызывался).
- Проверены скриншоты в `artifacts/quality/`; `git diff --check` проходит.

При доработке тестов исправлена коллизия аккаунтов параллельных прогонов
(UUID вместо времени) и прокрутка карточки перед проверкой свайпа: после
переноса колоды в раскрываемый блок она находится ниже первого экрана.

применённым и выполнить новую миграцию по database.md. Не выполнять baseline
CREATE TABLE поверх рабочей базы.

GitHub. Production backup не скачивался и не восстанавливался; проверен
