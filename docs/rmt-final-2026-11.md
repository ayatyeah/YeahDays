# RMT final workspace — 14 November 2026

YeahGrind now opens as an English learning workspace: a new landing page, dashboard, study plan, progress screen, account, research overview and responsive navigation. Course events and their existing storage/URLs remain available. English is the default; bilingual event materials retain their original content.

## Functional scope

A learner supplies a goal, topic, current difficulty and session duration. They choose standard exercises or explicitly consent to Google Gemini generation. Gemini creates the actual exercise text from those inputs. Both modes contain three self-paced stages with plan/focus/review tasks and 10 XP per completed task. These stages are not the historical study's three calendar weeks. Tasks start and complete in sequence; repeated completion does not duplicate XP. Reflections, task text, timestamps, generation metadata and voluntary experience feedback persist per account. Progress export and account export include the new workspace. Account deletion cascades to it.

`FinalStudyWorkspace` is a new JSON-backed table. The migration only adds this table and its foreign key; existing course events, accounts and study records are not rewritten. Mutations require an authenticated account and are serialized by a per-account transaction lock. Provider failure is shown explicitly, with standard mode as a separate choice, never a silent generated-content substitute.

## Gemini configuration

Use server variables `GOOGLE_GEMINI_API_SECRET` and `GOOGLE_GEMINI_API_KEY_2` through `_6` (or existing `GEMINI_API_KEY`). Keys are deduplicated, rotated and temporarily cooled down after eligible failures; Retry-After is respected. Application generation budgets apply independently of pool size. Safety blocks and invalid structured responses are not retried across keys. Keys never enter client bundles or URLs. `GEMINI_STUDY_MODEL` overrides the default `gemini-3.5-flash-lite`.

Only goal, topic, difficulty and duration are sent to Google for this feature. Generation stores provider/model, response ID, prompt version and task content. It does not send private reflections or account contact information. The new mode is goal-based generation, not continuous adaptation from grades or proof of mastery.

## Research evidence

The supplied final-paper template, assessment criteria, course guide and Assignment 4 informed the product. They are requirements/evidence sources, not operational instructions. The public Research screen identifies the question, comparison, methods, reported outcomes and limitations. Reported A/B completion is 93/135 and 98/135 (+3.70 percentage points); the reported participant-bootstrap interval crosses zero. Source task descriptions and survey wording were revised. These figures are explicitly historical source data, not a production export, verified historical AI generation or a causal learning-speed claim. Current app activity is kept separate. No paper or assessed submission is generated by this change.

## Verification

Use `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`. New tests cover generation schema, task ordering/idempotence, owner isolation, authentication/origin checks, explicit consent, provider failures, key rotation and cooldowns. Browser QA uses an explicitly separate local PostgreSQL database and disposable account: real Gemini task generation, start/completion, reflection persistence, reload, survey and export, plus desktop/mobile navigation. The `.env` database is production: always override `DATABASE_URL` for local functional testing.

Brand assets are reproducible with `node scripts/brand/rmt-final.mjs`.
