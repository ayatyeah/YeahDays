# Сквозные тесты

Тесты кликают по живому приложению так же, как человек: настоящий браузер,
профиль iPhone 13, настоящая база. Движок по умолчанию — **WebKit**, тот же,
что в Safari на iPhone: Chromium пропускает ровно те ошибки, которые потом
находятся на телефоне (жесты, клавиатура, `touch-action`, порядок гидрации).

## Запуск

```bash
npm run dev          # в одном окне: сервер на localhost:3000
npm run test:e2e     # в другом: весь набор
npm run test:e2e Друзья   # только сценарии, в имени которых есть «Друзья»
```

Скриншот и текст экрана на момент падения складываются в `e2e/.out`.

## Где что

- `harness.mjs` — каркас: браузер, тестовые аккаунты, проверки, прогон.
- `run.mjs` — запуск: проверяет сервер, подхватывает все файлы из `specs/`.
- `specs/01-auth.mjs` — регистрация, онбординг, вход, выход.
- `specs/02-today.mjs` — «Сегодня»: задачи и расписание по часам.
- `specs/03-deck-calendar-progress.mjs` — колода, календарь, прогресс.
- `specs/04-profile-nav.mjs` — профиль, настройки, навигация, жесты.
- `specs/05-social.mjs` — друзья, приглашения, челлендж, пары, напоминания.

## Правила, которые держат набор живым

- **Только тестовая база.** `harness.mjs` отказывается запускаться, если база
  не похожа на локальную dev — тесты создают и удаляют аккаунты.
- **Каждый тест заводит свои данные** через `newUser()` и ничего не ждёт от
  соседей: порядок прогона не должен ничего решать.
- **Аккаунты создаются прямо в базе.** У настоящей регистрации есть защита от
  перебора (30 в час с адреса), и набор упирался в неё на середине. Сама форма
  регистрации проверяется отдельным тестом, который проходит её по-человечески.
- **Состояние задаётся снимком** (`newUser({ state })`), а не прокликиванием
  онбординга: иначе каждый тест начинался бы с одних и тех же пяти экранов.
- **Ждать состояние, а не спать наугад.** Перед вводом в поля — дождаться,
  пока страница ожила (`waitUntil: "networkidle"`): до гидрации набранный
  текст теряется.
- **Имя теста — то, что делает человек**, а не имя компонента: по красной
  строке в выводе должно быть понятно, что именно сломалось для пользователя.
