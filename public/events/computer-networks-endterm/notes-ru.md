## 8. Сетевой уровень: как пакет попадает в другую сеть

**Главная мысль:** IP отвечает за адресацию и передачу пакета между сетями. Маршрутизатор выбирает следующий шаг по destination IP и таблице маршрутизации.

Путь данных: данные приложения → сегмент TCP/датаграмма UDP → пакет IP → кадр Ethernet → биты. Получатель разбирает оболочки в обратном порядке. На каждом маршрутизаторе старый кадр снимается и создаётся новый для следующего канала.

## Три характеристики IP

- **Connectionless:** перед отправкой IP не устанавливает соединение.
- **Best effort:** IP не гарантирует доставку, порядок и отсутствие дубликатов. Потерянный пакет сам не пересылает повторно.
- **Media independent:** IP может работать поверх Ethernet, Wi-Fi и других каналов.

Надёжность при необходимости обеспечивает TCP или приложение. «Ненадёжный» не означает «всегда теряет пакеты» — означает отсутствие гарантии и собственного восстановления.

## IPv4 и IPv6 headers

| Признак | IPv4 | IPv6 |
|---|---|---|
| Размер адреса | 32 бита | 128 бит |
| Основной заголовок | минимум 20 байт, длина может меняться | фиксированные 40 байт |
| Ограничение числа переходов | TTL | Hop Limit |
| Следующий протокол | Protocol | Next Header |
| Проверка основного заголовка | Header Checksum | такого поля нет |

Protocol в IPv4: ICMP = 1, TCP = 6, UDP = 17. TTL/Hop Limit уменьшается на маршрутизаторах; при нуле пакет отбрасывается. Source/Destination IP обычно сохраняются по пути, если нет NAT; MAC-адреса меняются при переходе на другой канал.

**MTU** — максимальный размер пакета, переносимого данным каналом. IPv4 допускает фрагментацию при соответствующих условиях; IPv6-маршрутизатор пакеты не фрагментирует, а сообщает источнику Packet Too Big. Источник должен подстроить размер.

## Локальный адресат или шлюз

ПК 192.168.1.10/24 отправляет данные на 192.168.1.20: сеть та же, кадр адресуется MAC получателя.

Если получатель 192.168.2.20: сеть другая, кадр адресуется MAC шлюза, например 192.168.1.1. При этом destination IP остаётся 192.168.2.20. Ошибка шлюза часто даёт ситуацию «локальная сеть работает, удалённые сети нет».

Таблица маршрутизации содержит connected, static и dynamic routes. Выбирается самый длинный совпавший префикс. Default route — маршрут последней надежды: IPv4 `0.0.0.0/0`, IPv6 `::/0`. В IOS `C` означает connected, `L` — local, `S` — static, `O` — OSPF.

Проверка: IOS `show ip route`; Windows `route print` или `netstat -r`.

**Ответ на открытый вопрос:** IP предоставляет логическую адресацию и маршрутизацию. Он работает без установления соединения, обеспечивает best-effort доставку и не зависит от среды передачи; подтверждения и повторные передачи при необходимости выполняются выше.

## Дополнения по вопросам банка

### Connected, local и remote: что означает next hop

**Next hop** — IP соседнего маршрутизатора, которому нужно передать пакет для дальнейшей доставки. **Remote route** ведёт к сети, которая не подключена к нашему маршрутизатору напрямую. Поэтому в вопросе «What routing table entry has a next hop address associated with a destination network?» выбираем **remote routes**.

| Запись | Что описывает | Пример |
| --- | --- | --- |
| C — connected | Сеть непосредственно подключённого интерфейса | C 192.168.1.0/24, GigabitEthernet0/0 |
| L — local | Собственный IP интерфейса маршрутизатора; пакет предназначен ему самому | L 192.168.1.1/32, GigabitEthernet0/0 |
| S — static, удалённая сеть | Вручную настроенный путь через соседа | S 192.168.2.0/24 via 192.168.1.254 |
| O — OSPF | Маршрут, изученный протоколом OSPF | O 192.168.3.0/24 via 192.168.1.254 |

Пакет для 192.168.2.10 отправится соседу 192.168.1.254. IP назначения пакета остаётся 192.168.2.10, а MAC назначения Ethernet-кадра — MAC соседа. C не требует соседнего роутера: получатель находится прямо на подключённой сети. L — не «любой локальный компьютер», а адрес самого роутера. S/O указывают источник маршрута, а remote — расположение сети. Не каждый remote route обязательно показывает явный next-hop IP: некоторые статические маршруты заданы выходным интерфейсом.

### Поля IP и MTU

IPv4 Version занимает 4 бита (0100). Protocol указывает следующий протокол: ICMP = 1, TCP = 6, UDP = 17. Header checksum проверяет только заголовок IPv4. TTL уменьшается при маршрутизации; при исчерпании пакет отбрасывается, обычно с ICMP Time Exceeded. В IPv6 основной заголовок — 40 байт; вместо TTL используется Hop Limit, checksum основного заголовка отсутствует.

MTU — максимальный размер IP-пакета, который переносит канал без фрагментации. Сетевой уровень получает ограничение от канального уровня; это ограничение **размера, а не скорости**. Для Ethernet обычно 1500 байт. При переходе на канал с меньшим MTU IPv4 может фрагментироваться, если DF не запрещает это; IPv6-роутер сообщает Packet Too Big, а размер корректирует отправитель.

### Адреса и повторение смежных тем

MAC обычно 48 бит (12 шестнадцатеричных цифр); IP — логический адрес, IPv4 32 бита, IPv6 128. В Ethernet сначала destination MAC, затем source MAC; в IP-заголовке source IP расположен перед destination IP. Без NAT IP конечных узлов сохраняются, а канальная оболочка меняется на маршрутизаторах. OSPF и BGP выбирают маршруты; IP переносит пакеты.

Для перевода октета в двоичный вид используй веса 128, 64, 32, 16, 8, 4, 2, 1: 192 = 11000000; 168 = 10101000; 11 = 00001011; 10 = 00001010. Для пяти подсетей нужно заимствовать 3 бита (8 вариантов). Для 2662 хостов нужны 12 host bits: 4094 доступных адреса, то есть /20. IP на L2-коммутаторе нужен для управления; 127.0.0.1 проверяет локальный стек. Голос и видео особенно чувствительны к задержке.

## Проверка по разделам NetAcad 8: что ещё нужно понимать

### Четыре операции L3 и решение хоста

1. Адресация: каждому участвующему IP-интерфейсу нужен адрес.
2. Инкапсуляция: источник добавляет IP-заголовок к транспортным данным.
3. Маршрутизация: каждый роутер выбирает следующий переход по destination IP.
4. Деинкапсуляция: конечный получатель снимает IP-заголовок и передаёт данные протоколу, указанному в Protocol/Next Header.

Хост различает «я сам», on-link и off-link. Loopback 127.0.0.1/::1 остаётся внутри компьютера; обычная loopback-проверка не тестирует кабель. В IPv4 on-link определяют IP и mask, в IPv6 — сведения о префиксах, обычно из RA. Default gateway IPv4 можно получить через DHCP или ввести вручную; IPv6 узнаёт default router из RA. DHCPv6 сам по себе default router не выдаёт.

### Все поля заголовков без путаницы

| IPv4 | Что означает |
| --- | --- |
| Version / IHL | Версия IP / длина IPv4-заголовка в 32-битных словах |
| DS | DSCP — класс обработки; ECN — сигнализация перегрузки |
| Total Length | Весь пакет, заголовок плюс payload |
| Identification, Flags, Fragment Offset | Связь фрагментов, разрешение/наличие фрагментации, позиция фрагмента |
| TTL | Ограничение времени жизни при пересылке |
| Protocol | Следующий протокол: ICMP 1, TCP 6, UDP 17 |
| Header Checksum | Проверка только IPv4-заголовка |
| Source / Destination | Конечные IP-адреса |
| Options / padding | Необязательные данные и выравнивание |

У IPv6 восемь основных полей: Version, Traffic Class, Flow Label, Payload Length, Next Header, Hop Limit, Source, Destination. Traffic Class соответствует классификации DS; Flow Label помечает поток для согласованной обработки. Payload Length не включает 40-байтовый основной заголовок. Next Header может указывать как TCP/UDP/ICMPv6, так и следующий extension header. Необязательные функции вынесены в extension headers, поэтому основной заголовок остаётся фиксированным.

### Как читать маршрут, а не угадывать букву

Запись `O 10.2.0.0/16 [110/20] via 192.168.1.254, 00:00:12, GigabitEthernet0/0` означает: сеть /16 изучена OSPF, [administrative distance/metric], сосед next hop, возраст и выходной интерфейс. D означает EIGRP. Число внутри скобок не длина маски и не TTL.

Сначала выбирается наиболее длинный совпавший префикс. Например, для 10.2.3.4 маршрут 10.2.3.0/24 конкретнее 10.2.0.0/16 и default 0.0.0.0/0. Для одинакового префикса сравниваются источники маршрутов/метрики по правилам протоколов; нельзя сравнивать метрики разных протоколов как одну общую шкалу. Нет подходящего маршрута, включая default — пакет отбрасывается.

Static задаётся вручную; dynamic (OSPF/EIGRP/BGP) обменивается информацией и адаптируется к изменениям после сходимости. Можно использовать оба подхода одновременно. В Wireshark раскрой IP-слой и найди адреса, TTL/Hop Limit, Protocol/Next Header и длины; сравнение пакетов на двух сторонах роутера показывает новый L2-кадр и уменьшенный TTL.

## 9. ARP и ND: как найти MAC

**Главная мысль:** знание IP ещё не даёт destination MAC для Ethernet-кадра.

## ARP для IPv4

1. Отправитель определяет, кто следующий сосед: конечный локальный узел или шлюз.
2. Ищет соответствие IPv4→MAC в ARP cache.
3. Если записи нет, отправляет ARP Request на `FF:FF:FF:FF:FF:FF`.
4. Владелец запрошенного IPv4 отвечает своим MAC, обычно unicast.
5. Соответствие временно сохраняется в RAM.

`arp -a` показывает кэш на ПК; `show ip arp` — на Cisco; `arp -d *` очищает динамический кэш на Windows. ARP не ищет MAC удалённого интернет-сервера через все маршрутизаторы: для удалённой сети нужен MAC локального шлюза.

Не путай две таблицы:

| Таблица | Соответствие |
|---|---|
| ARP | IPv4 → MAC |
| MAC address table коммутатора | MAC → порт/VLAN |

Коммутатор обучается по **source MAC**, пересылает по **destination MAC**. Unknown unicast и broadcast рассылаются в пределах VLAN по всем подходящим портам, кроме входного.

## Neighbor Discovery для IPv6

IPv6 не использует ARP и broadcast. ICMPv6 ND включает:

- **NS / NA:** Neighbor Solicitation / Advertisement — поиск соседа и разрешение IPv6→MAC.
- **RS / RA:** Router Solicitation / Advertisement — запрос и объявление параметров маршрутизатора/сети.
- **DAD:** проверка уникальности адреса, использующая NS.

ARP spoofing/poisoning подменяет IP→MAC и может перенаправить трафик через атакующего.

**Проверь себя:** пакет в другую сеть имеет destination IP удалённого хоста, а кадр — destination MAC локального шлюза.

## Дополнения по вопросам банка

### Как коммутатор принимает решение

Коммутатор **обучается по source MAC** и входному порту, а пересылает по **destination MAC**. Известный адрес отправителя обновляет таймер записи. Известный получатель — один нужный порт; неизвестный unicast или broadcast — все подходящие порты той же VLAN, кроме входного. Если получатель находится за входным портом, кадр не пересылается обратно.

ARP-кэш хранит IPv4 → MAC в RAM; динамические записи устаревают. Статическая запись широковещательного адреса вроде 192.168.1.255 → FF:FF:FF:FF:FF:FF сама по себе не означает атаку. IPv4 multicast MAC начинается с 01:00:5E; это группа, а не Ethernet broadcast FF:FF:FF:FF:FF:FF.

### Кого искать через ARP или ND

Сначала сравни сети отправителя и получателя по маске. Одна сеть — ищи MAC получателя. Разные — MAC шлюза. ARP не запрашивает MAC удалённого сервера через Интернет. В IPv6 Neighbor Solicitation обычно направляется в solicited-node multicast; Neighbor Advertisement сообщает адрес соседа. DAD тоже использует NS для проверки уникальности. Router Solicitation ищет роутеры, Router Advertisement объявляет параметры сети.

При вопросах про поля помни: MAC, FCS и 802.2 относятся к канальному уровню; IP и TTL — к сетевому; порты и TCP ACK — к транспортному.

## Детали NetAcad: ARP-кадр, сбой разрешения и пять сообщений ND

### Что именно находится в ARP-запросе

ARP передаётся прямо внутри Ethernet: отдельного IPv4-заголовка у ARP нет, хотя внутри сообщения есть IPv4 отправителя и цели. Destination MAC запроса — FF:FF:FF:FF:FF:FF; source MAC — адрес отправителя; EtherType 0x0806 сообщает, что payload нужно обработать как ARP. Broadcast-MAC определяет, кто принимает кадр, а EtherType — какой процесс его разбирает. Не путай эти два решения.

Все узлы VLAN принимают запрос, но в обычной ситуации отвечает только владелец target IPv4. В ответе destination MAC — MAC автора запроса, source MAC — MAC отвечающего устройства; это unicast. Получатель ответа сохраняет соответствие IP→MAC. Если ответа нет, MAC так и неизвестен: после попыток разрешения пакет будет отброшен, а не разослан broadcast как данные.

### Динамический кэш, статические записи и нагрузка

Динамические записи стареют по таймеру; срок зависит от системы. Статические записи не истекают таким способом, их удаляют административно. Очистка кэша заставляет устройство выполнить новое разрешение — она не меняет настройки адресов и не синхронизирует таблицы между устройствами. В начале общения возможна небольшая задержка на запрос/ответ. Большое число broadcast-запросов занимает канал и время обработки всех узлов; именно масштаб, а не сам факт ARP, может стать проблемой.

ARP не доказывает подлинность заявления «этот IP имеет такой MAC». При poisoning злоумышленник подменяет, например, строку шлюза. Сравнение `arp -a` с доверенным MAC помогает диагностировать подмену; одна неожиданная запись сама по себе ещё не доказывает атаку — интерфейс мог быть заменён.

### Пятое сообщение ND и уточнение про multicast

ND использует пять сообщений ICMPv6: NS, NA, RS, RA и Redirect. Redirect сообщает host более подходящий next hop; подробная настройка Redirect выходит за рамки модуля, но название и назначение входят в обзор. Для первоначального поиска MAC NS идёт в solicited-node multicast. Для проверки достижимости уже известного соседа NS может быть unicast: не запоминай ошибочное правило «все NS всегда multicast».

### Практикум без угадывания схемы

Для каждого Ethernet-перехода выпиши четыре поля: source/destination IP, source/destination MAC. IP конечных узлов без NAT одинаковы; MAC относятся к отправителю и следующему получателю именно на этом канале. В Packet Tracer сравни PDU до и после роутера, затем ARP/neighbor cache. Коммутатор между ними не становится destination MAC транзитного кадра. Если карточка требует конкретный порт или MAC на рисунке, без рисунка можно объяснить правило, но нельзя честно проверить конкретный адрес.

**Самопроверка:** ARP или IP-заголовок? Ethernet → ARP напрямую. Все принимают запрос или все отвечают? Принимают все в VLAN, отвечает владелец. Нет ответа? Доставка после попыток разрешения завершается неудачей. Какая пятая ND-команда? Redirect — лучший next hop.

Для противодействия подмене enterprise-коммутаторы могут использовать Dynamic ARP Inspection (DAI), проверяющий допустимость ARP-соответствий. Курс упоминает эту защиту, но её конфигурация выходит за рамки модуля.

## 10. Настройка Cisco IOS

## Режимы и память

| Приглашение | Режим | Как попасть |
|---|---|---|
| `R1>` | user EXEC | начальный вход |
| `R1#` | privileged EXEC | `enable` |
| `R1(config)#` | global configuration | `configure terminal` |
| `R1(config-if)#` | interface configuration | `interface ...` |
| `R1(config-line)#` | line configuration | `line console 0` / `line vty 0 4` |

`exit` — назад на один уровень; `end` или Ctrl-Z — в privileged EXEC. `?` — контекстная справка; Tab — дополнение команды.

**RAM:** running-config, ARP cache, routing table; данные теряются при отключении питания. **NVRAM:** startup-config. **Flash:** обычно образ IOS. Настройки running-config действуют сразу, но для сохранения после перезагрузки нужно `copy running-config startup-config`.

## Учебный пример настройки

Значения в угловых скобках ниже надо заменить; названия интерфейсов зависят от устройства.

```text
enable
configure terminal
hostname R1
enable secret <strong-enable-secret>
service password-encryption
banner motd #Authorized access only#
line console 0
 password <console-password>
 login
 exec-timeout 5 0
 exit
interface gigabitEthernet 0/0
 description LAN
 ip address 192.168.10.1 255.255.255.0
 ipv6 address 2001:db8:10::1/64
 no shutdown
 exit
ipv6 unicast-routing
end
copy running-config startup-config
```

`no shutdown` административно включает интерфейс. `description` — комментарий. `ipv6 unicast-routing` включает пересылку IPv6 между интерфейсами.

На L2-коммутаторе IP для управления задают SVI, например `interface vlan 1`, а шлюз — `ip default-gateway 192.168.10.1`. Это не превращает L2-коммутатор в маршрутизатор. Для работы SVI также нужны соответствующие условия активности VLAN/портов.

## SSH

```text
configure terminal
ip domain-name lab.example
username admin secret <strong-user-secret>
crypto key generate rsa
! При запросе размера ключа в учебной лаборатории выбери поддерживаемое значение, например 2048.
ip ssh version 2
line vty 0 4
 login local
 transport input ssh
 exec-timeout 5 0
end
copy running-config startup-config
```

Hostname уже задан. Нужны IP-доступность устройства, пользователь и RSA keys. `login local` использует локальную базу пользователей. `transport input ssh` разрешает SSH на VTY. SSH шифрует сеанс, Telnet — нет.

`service password-encryption` в классическом IOS скрывает открытые пароли слабой обратимой Type 7; это не полноценная защита секретов и не шифрование сетевого трафика. См. [Cisco о хранении секретов](https://www.cisco.com/c/en/us/about/trust-center/resilient-infrastructure/protecting-secrets.html).

## Что проверять

- `show ip interface brief` — IPv4 и Status/Protocol; рабочее состояние обычно up/up.
- `show ipv6 interface brief` — IPv6 интерфейсов.
- `show running-config` — действующие команды.
- `show startup-config` — сохранённая конфигурация.
- `show ip route` — маршруты.
- `ping` — достижимость; `traceroute` — промежуточные переходы.

## Дополнения по вопросам банка

### Режимы IOS и загрузка

`R1>` — user EXEC, ограниченные команды просмотра. `enable` → `R1#`, privileged EXEC. `configure terminal` → `R1(config)#`; `line console 0` → `(config-line)#`, `interface g0/0` → `(config-if)#`. `exit` возвращает на уровень выше; `end` или Ctrl+Z — в privileged EXEC.

Загрузка: POST/bootstrap → IOS (обычно Flash) → startup-config из NVRAM. Нет startup-config — возможен диалог первоначальной настройки. `copy running-config startup-config` сохраняет текущие настройки. Обратная команда **загружает и объединяет** сохранённые настройки с текущими, а не сохраняет изменения. `show version` показывает версию IOS и оборудование; `show ip interface brief` — адреса и состояния (up/up означает работу физического и канального уровней); `show ip route` — маршруты и выходные интерфейсы.

### Управление коммутатором и пароли

SVI — логический интерфейс VLAN, не физический порт. На L2-коммутаторе IP/маска SVI нужны для управления; `ip default-gateway` — чтобы сам коммутатор отвечал управляющим узлам из других сетей. Это не превращает его в IP-маршрутизатор.

Console — локальный out-of-band доступ; SSH/Telnet работают через сеть, AUX может использовать модем. `password` на линии требует `login`; `login local` использует локальную базу username. `enable secret` защищает privileged EXEC, а не вход на console. `service password-encryption` скрывает открытый текст в конфигурации, но старый Type 7 легко обратим.

Hostname в правилах курса начинается с буквы, заканчивается буквой или цифрой, не содержит пробелов; допустимы буквы, цифры и дефисы, длина меньше 64 символов. Пример: RM-3-Switch-2A4.

## Проверка понимания: настройка и диагностика роутера

### Когда no shutdown недостаточно

Команда снимает административную блокировку. Физический канал также требует кабеля/трансивера, работающего соседа и включённого порта на другом конце. `administratively down/down` — проверь shutdown; `down/down` — физический канал; `up/down` — line protocol/канальную настройку. `up/up` означает работу уровней 1–2, но не доказывает правильный IP, маршруты или доступность приложения. `description` служит подписью порта и не включает его.

Для SVI VLAN должна существовать и быть активна; обычно нужен хотя бы один активный порт этой VLAN в forwarding state. IP адресуется на `interface vlan 1`, а не произвольно на access-порт L2-коммутатора.

### Команда под конкретную проверку

| Нужно узнать | Команда | Почему именно она |
|---|---|---|
| Все IPv4 и состояния | show ip interface brief | Краткая таблица IP, Status, Protocol |
| IPv6 всех интерфейсов | show ipv6 interface brief | Включая link-local и global адреса |
| Какие сети достижимы | show ip route / show ipv6 route | Префикс, next hop и выходной интерфейс |
| Подробности порта | show interfaces | Состояния, ошибки и счётчики канала |
| IP-параметры порта | show ip interface / show ipv6 interface | Подробная конфигурация соответствующего протокола |
| Текущие/сохранённые команды | show running-config / show startup-config | Сравнение того, что действует сейчас и после перезапуска |
| IOS и загрузка | show version | Версия, оборудование, uptime, configuration register где поддерживается |

`?` показывает допустимые команды/аргументы в текущем контексте. `Tab` завершает однозначное слово. «Invalid input» может означать неверный режим, а не необходимость печатать полную команду: `conf t` допустима в #, но не в >.

### Разбор неисправного шлюза

PC 192.168.10.10/24 и SVI 192.168.10.2/24 используют роутер 192.168.10.1 как gateway. Сосед .20 доступен напрямую; 10.1.1.10 требует роутера. На ПК gateway настраивается в ОС, на L2-коммутаторе — `ip default-gateway 192.168.10.1`; настройка коммутатора не раздаёт шлюз его клиентам. Для IPv6 шлюз может быть link-local адресом роутера и изучаться из RA — одинаковый глобальный префикс для адреса шлюза не требуется.

Порядок диагностики: сверить адрес/маску/шлюз с таблицей → проверить Status/Protocol → ping своего шлюза → ping удалённого IP → проверить маршруты туда и обратно → исправить причину → повторить тест и записать изменение. Не считать один timeout доказательством обрыва: ICMP может фильтроваться. `!` в IOS ping — ответ, `.` — таймаут, `U` — unreachable; код ICMP уточняет причину.

### Сохранить, загрузить или откатить

`copy running-config startup-config`: сохранить действующие команды для следующего запуска. `copy startup-config running-config`: объединить сохранённые команды с текущими, а не гарантированно удалить все новые команды. В учебной задаче о полном отказе от несохранённых изменений выбирается reload без сохранения: при старте загрузится старый startup-config. В реальной сети перезагрузка прерывает работу.

### Практическая самопроверка

Объясни без подсказки: почему SVI с IP не гарантирует SSH; почему локальный ping может работать при неверном gateway; чем сохранение отличается от применения настройки; почему роутер меняет L2-оболочку на каждом канале. Для лаборатории собери топологию, настрой адреса и доступ, проверь связность и show-команды, затем сохрани настройки. Названия интерфейсов зависят от модели: G0/0 и G0/0/0 нельзя механически подменять.

В архиве есть описания лабораторных и заголовки видео 10.4.1–10.4.2, но пустые транскрипты этих двух видео. Их содержимое и конкретные ответы недоступных PT-файлов не выданы здесь за повторно просмотренные.

## 11. IPv4 и подсети

**Главная мысль:** маска делит 32-битный адрес на network и host части. Адрес сети получается побитовым AND адреса и маски.

## Таблица, которую стоит выучить

| Префикс | Маска | Размер блока | Пригодных хостов в обычной LAN |
|---|---|---:|---:|
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /29 | 255.255.255.248 | 8 | 6 |
| /30 | 255.255.255.252 | 4 | 2 |

Если h = 32 − prefix, всего адресов 2^h, обычно хостов 2^h−2. Отнимаются network address и broadcast. /31 для point-to-point и /32 — исключения, к которым нельзя механически применять эту формулу.

## Как решить задачу за минуту

Адрес `192.168.10.77/28`:

1. /28 → маска .240, размер блока 256−240=16.
2. Границы: 0,16,32,48,64,80… Число 77 лежит между 64 и 79.
3. Network: `192.168.10.64`.
4. Broadcast: `192.168.10.79`.
5. Хосты: `.65`–`.78`, всего 14.

Пример `/22`: `172.16.16.0/22` имеет маску 255.255.252.0. Шаг третьего октета 4, диапазон 16–19. Broadcast `172.16.19.255`, хостов 1022.

## Число подсетей и VLSM

Для N одинаковых подсетей нужно b бит, чтобы 2^b ≥ N. Пять сетей: 2²=4 мало, 2³=8 достаточно → занять 3 бита. Из /24 получим /27.

VLSM позволяет разные размеры подсетей. Например внутри /24 нужны 100, 50 и 20 хостов: /25 (126), /26 (62), /27 (30). Размещаем от большей к меньшей: `.0/25`, `.128/26`, `.192/27`. Блоки должны быть выровнены и не пересекаться.

## Специальные диапазоны

| Диапазон | Назначение |
|---|---|
| 10.0.0.0/8 | private |
| 172.16.0.0/12 | private: 172.16–172.31 |
| 192.168.0.0/16 | private |
| 127.0.0.0/8 | loopback, типичный пример 127.0.0.1 |
| 169.254.0.0/16 | link-local, часто результат неудачного DHCP |
| 224.0.0.0/4 | multicast |
| 255.255.255.255 | limited broadcast |

Не вся сеть 172/8 частная. Broadcast конкретной подсети — последний её адрес, а не обязательно адрес с последним октетом 255.

## Дополнения по вопросам банка

### Считать адрес относительно маски

Один адрес может быть host, network или broadcast в зависимости от префикса. 192.168.1.96 — адрес сети при /27, но адрес хоста в сети 192.168.1.64/26. 192.168.1.15/29 — broadcast сети .8/29. Для .17/30: сеть .16, хосты .17–.18, broadcast .19; для .35/29: сеть .32, хосты .33–.38, broadcast .39.

Маска /20 = 255.255.240.0. /26 оставляет 6 host bits, даёт 64 адреса и 62 обычных хоста; из одного /24 получаются четыре /26. Для 90 или 126 хостов нужен /25: 128 адресов, 126 доступных. Для 2662 — /20. В VLSM сначала выделяй крупнейшую сеть; свободное место считай по реальным выделенным блокам, а не по количеству компьютеров.

### Специальные адреса и доставка

Unicast — один получатель, multicast — выбранная группа, broadcast — все в широковещательном домене. Limited broadcast 255.255.255.255 отличается от directed broadcast конкретной подсети. Маршрутизатор по умолчанию не переносит broadcast в другую сеть; VLAN/подсети уменьшают область его распространения.

169.254.0.0/16 — link-local, часто признак отсутствия ответа DHCP. DHCP Discover может идти от 0.0.0.0 к 255.255.255.255. 127/8 — loopback. 192.0.2/24, 198.51.100/24 и 203.0.113/24 — документационные сети; 240/4 зарезервирован. Поэтому «не RFC 1918» ещё не означает обычный публичный адрес. IANA координирует глобальные ресурсы, RIR распределяют региональные блоки провайдерам и организациям.

## Аудит NetAcad 11: подсети от простого к сложному

### AND и длина префикса

Битовая операция: 1 AND 1 = 1; все остальные сочетания дают 0. Поэтому mask сохраняет network bits и обнуляет host bits. /24, /16 и /8 проходят по границам октетов, но большинство задач требуют границы внутри октета. Шаг блока в меняющемся октете = 256 − октет маски. Например, /22: 255.255.252.0, шаг 4 в третьем октете; 172.16.130.7 принадлежит 172.16.128.0/22, broadcast 172.16.131.255.

### Сколько сетей и сколько хостов — две разные проверки

Для N сетей выбери минимальное b, где 2^b ≥ N. Для H хостов выбери минимальное h, где 2^h−2 ≥ H. Новый префикс = старый+b, но при этом 32−новый префикс должен оставлять достаточно host bits.

100 сетей из 172.16.0.0/16: 6 бит дают 64, 7 дают 128 → /23. В каждой 512 адресов, 510 usable; шаг 2 в третьем октете. 1000 сетей из 10.0.0.0/8: 9 бит дают 512, 10 дают 1024 → /18, маска 255.255.192.0. В каждой 16384 адреса, 16382 usable; шаг 64 в третьем октете, после 10.0.192.0/18 идёт 10.1.0.0/18.

### Полный пример VLSM

Нужно 60, 28, 12, 2 хоста из 192.168.10.0/24. Сортируем по убыванию и выделяем: 60→.0/26 (.1–.62), 28→.64/27 (.65–.94), 12→.96/28 (.97–.110), 2→.112/30 (.113–.114). Broadcast соответственно.63, .95, .111, .115. Все начала выровнены и блоки не пересекаются. Свободное пространство после.115 нельзя называть одним произвольным CIDR-префиксом: при дальнейшей раздаче снова учитывай границы блоков.

### План адресации и старые классы

Исторические Class A/B/C имели default /8, /16, /24; современная CIDR-маска задаётся явно и важнее первого октета. Class D обозначал multicast 224/4, Class E — reserved 240/4. Classful-таблицы полезны для старых формулировок, но не заменяют subnet mask.

Сегментируют сети ради уменьшения broadcast, разделения подразделений/политик безопасности и удобного управления. До расчёта составь список LAN/WAN/DMZ, количества хостов и запаса роста. Клиентам обычно DHCP; шлюзам, серверам, принтерам и управлению сетевым оборудованием — предсказуемые адреса (static или резервирование). Исключи их из динамического пула. Public адрес можно использовать и внутри сети, если он выделен организации; private нельзя просто объявить публично маршрутизируемым.

Для PT-лабы: выпиши network/prefix, usable range, broadcast иgateway каждой LAN; назначь адреса, проверь интерфейсы up/up иping локального шлюза/удалённого узла. Метод здесь объяснён; результат конкретного отсутствующего PT-файла не считается выполненным.

## 12. IPv6

128 бит записываются восемью группами по 16 бит, в hex. Пример: `2001:0db8:0000:abcd:0000:0000:0000:0001` → `2001:db8:0:abcd::1`.

Правила: ведущие нули внутри группы можно убрать; одну последовательность нулевых групп — заменить `::`. Использовать `::` дважды нельзя. При равных самых длинных нулевых последовательностях стандартная запись сокращает первую.

## Типы адресов

- **GUA:** глобальный unicast; в типичных учебных примерах 2000::/3.
- **LLA:** link-local FE80::/10; только один канал, через router не пересылается.
- **Loopback:** ::1/128.
- **Unspecified:** ::/128 — отсутствие назначенного адреса в соответствующих процедурах.
- **Multicast:** FF00::/8; FF02::1 — все узлы, FF02::2 — маршрутизаторы данного канала.
- **Anycast:** один unicast-адрес назначен нескольким интерфейсам, доставка ближайшему по метрике маршрутизации.

**Broadcast в IPv6 отсутствует.** Не путай link-local и private IPv4: это разные механизмы и области действия.

## Префиксы и подсети

Для обычной LAN применяется /64. В `2001:db8:cafe:1111:2222:3333:4444:5555/64` первые четыре группы — префикс, последние четыре — interface ID. Если провайдер дал /48, четвёртая группа (`1111`) — 16-битный subnet ID. Это даёт 2^16 = 65536 подсетей /64.

## Как назначается адрес

| Метод | Адрес | Другие параметры |
|---|---|---|
| SLAAC | хост формирует по префиксу RA | из RA, по поддерживаемым возможностям |
| SLAAC + stateless DHCPv6 | формирует сам | дополнительные параметры, например DNS, через DHCPv6 |
| Stateful DHCPv6 | выдаёт DHCPv6 server | DHCPv6 |

Default gateway обычно узнают из RA, а не DHCPv6. RS — запрос маршрутизаторам, RA — ответ/объявление маршрутизатора. DAD проверяет, не занят ли адрес.

EUI-64: MAC делится пополам, вставляется FFFE, инвертируется U/L-бит. Другой вариант — сгенерированный interface ID. Не все устройства используют MAC для IPv6-адреса.

Совместная работа: dual stack — два стека; tunneling — пакет внутри пакета; translation — преобразование между протоколами.

## Дополнения по вопросам банка

### Префикс, subnet ID и interface ID

Global unicast удобно разделять на глобальный префикс провайдера, subnet ID организации и interface ID узла. Для /48 провайдера и LAN /64 под подсети остаётся 16 бит; для /32 → /64 — 32 бита. Interface ID обычной /64 занимает последние 64 бита. Не путай subnet ID с полным сетевым префиксом.

Пример: 2001:db8::1000:a9cd:47ff:fe57:fe94 раскрывается в 2001:db8:0000:1000:a9cd:47ff:fe57:fe94. Сеть /64 — 2001:db8:0:1000::/64, interface ID — a9cd:47ff:fe57:fe94. При делении 2001:db8::/48 на /52 заимствуются 4 бита: 16 сетей, четвёртый hextet 0000, 1000, …, f000. Последняя — 2001:db8:0:f000::/52.

### Адреса и сообщения, которые легко перепутать

fe80::/10 — link-local; пакеты не маршрутизируются за пределы канала. ff02::1 — все узлы на канале; ff02::2 — все роутеры. Host отправляет RS, роутер отвечает RA. Solicited-node multicast используется ND, его префикс ff02::1:ff00:0/104. IPv6 не использует broadcast.

Interface ID может создаваться случайно или по modified EUI-64: MAC разделяется пополам, вставляется ff:fe и инвертируется U/L-бит первого байта. SLAAC не означает обязательное использование MAC. IPv6 устраняет необходимость NAT ради экономии адресов, но не заменяет firewall. /64 — обычный LAN-префикс, не обязательная длина абсолютно каждого IPv6-канала.

## Практическая настройка IPv6 и точные границы понятий

### ULA, LLA и документационные адреса

Unique-local FC00::/7 (обычно локально генерируемые FD…) предназначены для внутреннего общения в организации или ограниченной группе сайтов. Их можно маршрутизировать между внутренними подсетями, но обычно не в глобальном Интернете. LLA FE80::/10 не покидает один link. Поэтому ULA и LLA нельзя считать синонимами. 2001:db8::/32 — документационный диапазон: он имеет привычный формат GUA в упражнениях, но не предназначен для адресации реального публичного сервиса. IPv6 сам по себе не заменяет фильтрацию и безопасность.

### Мини-лаборатория IOS

```text
configure terminal
ipv6 unicast-routing
interface gigabitethernet 0/0/0
ipv6 address 2001:db8:acad:1::1/64
ipv6 address fe80::1 link-local
no shutdown
end
show ipv6 interface brief
show ipv6 route
```

`ipv6 address …/64` задаёт GUA; пробел перед `/64` не нужен. `link-local` явно задаёт LLA. Одного адреса на интерфейсе недостаточно для forwarding между сетями: нужна глобальная `ipv6 unicast-routing`. `show ipv6 interface brief` показывает GUA/LLA и up/up (физический/канальный уровни); `show ipv6 route` — IPv6 маршруты. В `show running-config` ищи включение маршрутизации. На Windows адрес, prefix length и default gateway задаются отдельно; gateway может быть LLA роутера.

LLA автоматически появляется при включении IPv6 и может создаваться из EUI-64 или другого IID-алгоритма. Он должен быть уникальным на link, а не во всём Интернете: одинаковый fe80::1 на двух раздельных link допустим. При обращении к LLA иногда требуется указать исходный интерфейс/zone, иначе непонятно, на каком link искать соседa.

### EUI-64 по шагам

MAC 00:1A:2B:3C:4D:5E → разделить 00:1A:2B и 3C:4D:5E → вставить FF:FE → 00:1A:2B:FF:FE:3C:4D:5E → инвертировать U/L-бит (XOR 0x02 первого байта) → 02:1A:2B:FF:FE:3C:4D:5E. IID: 021a:2bff:fe3c:4d5e. Не путай инверсию одного бита с перестановкой всего MAC. Случайные/stable privacy IID не обязаны содержать FFFE. DAD проверяет уникальность перед обычным использованием адреса.

### Три RA-сценария без ловушки про gateway

SLAAC создаёт адрес на host; SLAAC + stateless DHCPv6 добавляет серверные параметры вроде DNS; stateful DHCPv6 выдаёт сам адрес и отслеживает аренду. Во всех этих учебных сценариях default router узнаётся из RA, не из обычного DHCPv6. RA не создаёт уникальный IID за host: тот выбирается отдельно. Получение DNS из RA зависит от поддерживаемых опций и реализации.

### План подсетей и multicast

Для /48 2001:db8:acad::/48 выдели LAN 2001:db8:acad:1::/64, следующую LAN :2::/64 и третью :3::/64. Меняется subnet ID, а длина IID остаётся 64 бита. Не вычитай IPv4 network/broadcast «минус два» из количества IPv6-подсетей: IPv6 не имеет broadcast. FF02::1 — все nodes канала; FF02::2 — routers. Solicited-node multicast использует последние 24 бита unicast/anycast адреса, чтобы уменьшить число получателей NS. Для …:1234:5678 это FF02::1:FF34:5678. При заданиях с отсутствующей схемой сначала нужны размеры site/sub-site/subnet полей: без них ответ 16 или 256 не выводится.

## 13. ICMP, ping и traceroute

ICMP сообщает об ошибках IP и помогает диагностике. Он не гарантирует доставку и не заменяет TCP.

**ping:** Echo Request → Echo Reply. Позволяет оценить достижимость и round-trip time (RTT). Ответ loopback подтверждает локальный стек; ответ шлюза — достижимость шлюза. Ни один из них сам по себе не доказывает доступ ко всему интернету.

**traceroute / tracert:** пробные пакеты с TTL/Hop Limit 1,2,3… Маршрутизатор, у которого значение исчерпалось, отвечает Time Exceeded. Так видны промежуточные hop. Конкретный транспорт проб зависит от реализации.

В IOS `!` — ответ, `.` — таймаут, `U` — unreachable. Фильтрация ICMP и ограничение частоты ответов могут скрыть рабочий узел: один `*` в трассировке не равен доказанной поломке.

Порядок диагностики: IP/маска → loopback → локальный сосед/шлюз → удалённый IP → доменное имя. Если IP работает, имя нет — проверь DNS. `ipconfig`, `nslookup`, `ping`, `tracert` отвечают на разные вопросы.

Ловушка: «ICMP code 0» без типа недостаточно. У ICMPv4 Type 3/Code 0 — network unreachable; у Echo Reply Type 0/Code 0 — успешный ответ. В IPv6 неизвестный Next Header сообщается через Parameter Problem; не переносите таблицу кодов IPv4 на IPv6. [RFC 4443](https://datatracker.ietf.org/doc/html/rfc4443).

## Дополнения по вопросам банка

### Что действительно доказывают ping и traceroute

Успешный ping показывает достижимость и время туда-обратно (RTT), а не исправность каждого приложения. Рост RTT относительно baseline — признак возросшей задержки. Неудача может означать фильтрацию ICMP, неверные адреса, отсутствие маршрута или неисправность; по одному timeout нельзя выбрать единственную причину.

Extended ping в IOS: введи `ping` без адреса, затем выбери extended commands и source address/interface. Это позволяет проверить доставку именно от выбранного интерфейса, а не от обычного адреса выходного интерфейса. Windows `tracert -6` явно использует IPv6.

### ICMP: значение имеют и type, и code

В ICMPv4 Echo Reply — type 0/code 0, а Destination Network Unreachable — type 3/code 0. Одного «code 0» без type недостаточно. TTL/Hop Limit исчерпан — Time Exceeded. Неизвестный IPv6 Next Header может вызвать Parameter Problem. Ping ::1 или 127.0.0.1 проверяет свой стек, не кабель и не провайдера.

`ipv6 unicast-routing` включает IPv6-маршрутизацию; на подходящих интерфейсах роутер обычно начинает отправлять RA. Наличие команды проверяй в `show running-config`. Для задачи с картинкой сначала найди реальный gateway и нужный интерфейс: адрес сервера и адрес шлюза выполняют разные роли.

## ICMP: полный разбор сообщений и результатов

### Матрица сообщений

| Сообщение | Когда возникает | Что из него следует |
|---|---|---|
| Echo Request / Echo Reply | Проверка ping | Проверен двусторонний обмен Echo с указанным адресом |
| Destination Unreachable | Узел/роутер не смог доставить пакет | Нужны type и code для причины; это не гарантия, что цель выключена |
| Time Exceeded | TTL/Hop Limit исчерпан при пересылке | Проба достигла отвечающего роутера; это основа traceroute |
| Packet Too Big (ICMPv6) | Пакет больше MTU следующего канала | Отправитель должен уменьшить размер; IPv6-роутер не фрагментирует |
| Parameter Problem | Некорректное поле/неизвестный Next Header | Ошибка структуры/интерпретации пакета |
| RS / RA | Поиск роутеров и объявление IPv6-параметров | Хост запрашивает, роутер объявляет префикс и сведения о gateway |
| NS / NA | IPv6 neighbor resolution, DAD, проверка соседа | Выяснение адреса соседа или конфликт tentative-адреса |
| Redirect | Роутер сообщает лучший локальный next hop | Это не протокол построения всей таблицы маршрутов |

Для ICMPv4 Destination Unreachable type 3: code 0 network, 1 host, 2 protocol, 3 port. Не переносить эти номера на ICMPv6. ICMP сообщает об ошибке, но не повторяет потерянный пакет и не превращает IP в надёжный транспорт.

### Traceroute на примере трёх роутеров

Проба TTL=1 истекает на R1 → R1 возвращает Time Exceeded. TTL=2 истекает на R2, TTL=3 — на R3, TTL=4 достигает цели. Конец трассы определяется иначе: при ICMP Echo-пробах это Echo Reply, при классических UDP-пробах к закрытому порту — Port Unreachable. Поэтому фраза «все ответы трассировки — Time Exceeded» неверна.

RTT каждой строки измеряется от источника до отвечающего hop и обратно. Разность соседних строк не является точным временем одного линка: маршруты ответов могут отличаться. `*` — ответ не получен вовремя, а не доказанный отказ роутера. Если более поздние hops отвечают, трафик проходит через молчащий участок.

### Лестница проверки

1. Loopback 127.0.0.1 / ::1: локальная реализация IP, без проверки кабеля и настроек gateway.
2. Сосед или default gateway: связь в локальной сети; доступ дальше пока не доказан.
3. Удалённый IP: двусторонний путь для ICMP через сеть, но не работоспособность HTTP/почты.
4. Доменное имя: добавляет проверку DNS; `nslookup` отделяет её от Echo. Имя разрешилось, но ping молчит — DNS уже мог сработать.

Первый ping иногда теряется во время ARP/ND; повтори серию и смотри процент успеха, а не один пакет. Для baseline запиши адрес источника/цели, время проверки, потери и RTT, затем сравнивай сопоставимые измерения. Рост RTT означает возможную задержку; он не измеряет пропускную способность напрямую.

### Важная граница курса

RS/RA особенно важны в IPv6, но исторически существуют и в IPv4 Router Discovery ([RFC 1256](https://www.rfc-editor.org/info/rfc1256/)). Поэтому вопрос банка с предложением выбрать ровно два общих ICMP-сообщения из RS, RA и Redirect неоднозначен. IPv6 unknown Next Header описан как Parameter Problem в [RFC 4443](https://www.rfc-editor.org/info/rfc4443/). Такие карточки помечены и не используются как однозначный тест.

## 14. TCP и UDP

**Главная мысль:** IP доводит пакет до устройства, транспортный уровень помогает доставить данные нужному приложению и различать разговоры.

| Свойство | TCP | UDP |
|---|---|---|
| Соединение | устанавливается | не устанавливается |
| Доставка | ACK и повторные передачи | гарантии и повторов нет |
| Порядок | восстанавливается | UDP не упорядочивает |
| Управление потоком | есть | нет |
| Заголовок | минимум 20 байт | 8 байт |
| Примеры курса | HTTP, FTP, SMTP | VoIP, TFTP, DNS-запросы |

UDP checksum умеет обнаруживать повреждение; отсутствие надёжности не означает отсутствие проверки. Для IPv6 UDP checksum в общем случае обязателен, с узкими специальными исключениями. [RFC 8200](https://datatracker.ietf.org/doc/html/rfc8200).

## Порты и sockets

Socket = IP:port, например `192.168.1.10:49152`. Для различения обмена учитываются адреса, порты и транспортный протокол. Клиент использует временный порт, сервер — известный порт службы.

- 0–1023: well-known/system.
- 1024–49151: registered/user.
- 49152–65535: dynamic/private.

Запрос HTTP: клиент `10.1.1.10:49152` → сервер `10.1.1.254:80`; в ответе роли source/destination меняются.

## TCP handshake и завершение

Открытие: SYN → SYN+ACK → ACK. SYN синхронизирует начальные номера, ACK подтверждает. Типичное закрытие: FIN → ACK, затем FIN → ACK в другом направлении; сообщения могут объединяться, поэтому «всегда ровно четыре» слишком строго.

Sequence number — номер байта в потоке. ACK — номер следующего ожидаемого байта. Если приняли байты 1–4500, ACK = 4501, а не 4500.

Receive window сообщает, сколько данных получатель готов принять: это **flow control**. Sliding window позволяет послать несколько сегментов без ожидания ACK после каждого. **Congestion control** отдельно реагирует на перегрузку сети и уменьшает объём неподтверждённых данных.

UDP хорош, когда небольшая задержка важнее повторной передачи старых данных или восстановление выполняет само приложение. Это не утверждение, что любое видео всегда использует UDP: потоковое видео может идти по TCP/QUIC.

## Дополнения по вопросам банка

### Заголовки, порты и соединения

UDP: 8 байт, четыре поля — source port, destination port, length, checksum. TCP: минимально 20 байт; sequence number, acknowledgment, flags и window обеспечивают функции, которых нет в UDP. UDP не восстанавливает исходный порядок доставки и не повторяет потерянные датаграммы. Его checksum — проверка ошибок, а не гарантия доставки.

Well-known ports: 0–1023; registered: 1024–49151; dynamic/private: 49152–65535. Клиентский исходный порт помогает отличать разговоры приложений. ОС может выбирать ephemeral-порты из собственного диапазона: не каждый временный порт обязательно >=49152. TCP-соединение различается протоколом, source/destination IP и source/destination port.

`netstat` показывает соединения, адреса/порты и состояния; `netstat -r` — таблицу маршрутов; `ipconfig` — IP-настройки. Destination port 80 обычно HTTP, 25 SMTP, 53 DNS; исходный порт клиента не обязан совпадать с портом службы.

### ACK, окно и завершение

ACK — следующий ожидаемый **байт**: после байтов 4001–4500 ожидается ACK 4501. Receive window ограничивает неподтверждённые данные по возможностям получателя (flow control); congestion control реагирует на перегрузку сети. Открытие: SYN → SYN/ACK → ACK. Типичное закрытие: FIN → ACK и FIN → ACK с другой стороны; некоторые сообщения могут объединяться. Сегментация TCP относится к транспорту, фрагментация IP — к сетевому уровню.

## Аудит NetAcad 14: как работает транспорт

### Два направления TCP и номера байтов

TCP — двунаправленный байтовый поток; у каждого направления свои sequence/ACK. При открытии клиент отправляет SYN с ISN=x; сервер отвечает SYN+ACK с собственным ISN=y и ACK=x+1; клиент подтверждает ACK=y+1. SYN и FIN занимают по одной позиции sequence space. ACK подтверждает следующий ожидаемый байт, а не номер последнего пакета. После байтов 1001–1500 ожидается 1501. Наличие ACK не означает, что приложение уже обработало файл — это подтверждение TCP-получения.

Если данные 1501–2000 потеряны, а 2001–2500 пришли, cumulative ACK остаётся 1501 до закрытия пробела. TCP может буферизовать поздние данные; повторная передача вызывается таймерами/сигналами потерь. Закрытие каждого направления отдельно: FIN→ACK; другое направление ещё может отправлять данные до своего FIN. RST — аварийный сброс, не обычное четырёхшаговое закрытие.

### Все поля и их назначения

TCP: source/destination port, sequence number, acknowledgment number, data offset (длина заголовка), reserved, control flags, window, checksum, urgent pointer; options/padding добавляются при необходимости. Курс группирует их в 10 основных полей минимум 20 байт. Flags: SYN — синхронизация, ACK — значимое acknowledgment поле, FIN — конец данных направления, RST — сброс, PSH — передача приложению, URG — urgent pointer. Checksum проверяет TCP-заголовок и данные с псевдозаголовком, а не гарантирует доставку.

UDP: два порта, length, checksum, всего 8 байт. Length включает заголовокUDP и данные. Нет окна, sequence/ACK и handshake. Приложение само выбирает, как пережить потерю/перестановку. TFTP добавляет собственный обмен подтверждениями поверх UDP; это не превращает его транспорт в TCP.

### Не путай MSS, MTU, receive window и congestion window

MTU — размер IP-пакета на канале. MSS — максимальные TCP-данные в одном сегменте, без TCP/IP-заголовков; значение объявляется как TCP option при handshake. При MTU 1500, IPv 4 header 20 иTCP header 20 MSS=1460. При IPv 6 base 40 иTCP 20 без дополнительных заголовков —1440. Options/туннели могут уменьшать полезную нагрузку.

Receive window (rwnd) защищает буфер получателя, congestion window (cwnd) ограничивает нагрузку на сеть. Фактическая отправка ограничена обоими. Sliding window продвигается с ACK и позволяет нескольким сегментам находиться в полёте. Нельзя путать окно 6000 байт с обязательным размером одного пакета или утверждать, что ACK приходит только после полного заполнения окна.

### Серверы, клиенты и наблюдение

Сервер слушает service port, клиент выбирает доступный временный source port. Ответ сервера меняет source/destination ports местами. Один listening port может обслуживать много соединений благодаря различным socket pairs; клиенты за NAT могут иметь один public IP, но разные ports. netstat показывает local/foreign endpoints и состояния TCP; в Wireshark сравни SYN/SYN-ACK/ACK, Seq/Ack/Window и повторные передачи. В PT Simulation можно наблюдать HTTP/TCP иDNS/UDP, но это упражнение не выполнено автоматически самим чтением конспекта.

## 15. Прикладной уровень

В TCP/IP application layer объединяет OSI application, presentation и session. Presentation связана с форматами, кодированием/сжатием; session — с управлением диалогом; application — с сетевыми сервисами приложений.

## Протоколы и порты

| Сервис | Порт в базовых примерах | Для чего |
|---|---|---|
| FTP | TCP 21; data TCP 20 в active mode | передача файлов |
| SSH | TCP 22 | защищённое управление |
| Telnet | TCP 23 | незашифрованное управление |
| SMTP | TCP 25 | отправка/пересылка почты |
| DNS | UDP/TCP 53 | записи имён |
| DHCPv4 | UDP 67 server, 68 client | выдача IP-настроек |
| TFTP | UDP 69 для начального запроса | простой перенос файлов |
| HTTP | TCP 80 в классической модели | веб |
| POP3 | TCP 110 | получение почты |
| IMAP | TCP 143 | серверный почтовый ящик |
| HTTPS | 443 | защищённый веб |
| SMB | TCP 445 | файлы и принтеры |

Это учебная таблица: существуют защищённые почтовые порты, пассивный FTP и HTTP/3 поверх QUIC/UDP. Для MCQ ориентируйся на конкретную формулировку.

## DNS

A → IPv4, AAAA → IPv6, MX → mail exchanger, NS → authoritative nameserver, CNAME → alias. `.com` — top-level domain. DNS-сервер не обязан отказывать только потому, что имя не в его зоне: может использовать рекурсию/пересылку. `nslookup` проверяет разрешение имени; DNS работает и по UDP, и по TCP.

## DHCP

DORA: Discover → Offer → Request → Acknowledge. Клиент без адреса ищет сервер broadcast-сообщением. DHCP выдаёт адрес на время аренды и параметры сети. На домашней сети эту роль часто выполняет роутер. Адрес 169.254.x.x вместо ожидаемого DHCP-адреса — повод проверить доступность сервера.

## HTTP и почта

GET получает ресурс; POST отправляет данные; PUT создаёт/заменяет ресурс по указанному адресу. HTTPS использует TLS для защиты HTTP.

SMTP отправляет почту, POP3 получает её на клиент, IMAP поддерживает централизованное хранение и синхронизацию. POP3 может оставлять копии, поэтому «всегда удаляет с сервера» неверно.

FTP имеет control и data connection, умеет upload/download. SMB предоставляет совместные файлы/принтеры и длительные сеансы; не ограничен Windows.

Client/server: клиент инициирует запрос, сервер предоставляет сервис. При upload ПК всё ещё клиент. P2P: узел может быть и клиентом, и сервером; выделенный сервер не обязателен.

## Дополнения по вопросам банка

### Роли и уровни приложений

Client/server: клиент инициирует запрос даже при **загрузке файла на сервер**. P2P: участник может одновременно быть клиентом и сервером; ресурсы распределены, выделенный сервер не обязателен. Общая папка или принтер домашнего ПК — пример P2P. Это роли приложений, а не расположение устройств.

TCP/IP application объединяет OSI application (протоколы приложений), presentation (форматы, кодирование, сжатие: GIF/JPG/MKV) и session (установление и поддержание диалога). Отправка веб-запроса: HTTP → TCP → IP → Ethernet; получение — наоборот.

### DNS, почта и файлы

DNS A → IPv4; AAAA → IPv6; NS → авторитетные DNS-серверы; MX → почтовые серверы домена. Сервер вне своей зоны не обязан сразу возвращать ошибку: возможны рекурсия, пересылка или referral. `nslookup` запрашивает DNS и показывает используемый сервер. В www.cisco.com верхний домен — .com. DNS использует UDP и TCP 53: обычные запросы часто UDP, transfer зоны TCP; TCP возможен и у клиента.

SMTP отправляет почту; POP3 скачивает её в клиент (копию можно оставить настройкой); IMAP синхронизирует серверные папки и удобен для нескольких устройств и централизованного хранения. FTP использует отдельные control/data соединения: control TCP 21, в active FTP серверный data port 20; passive использует согласованный порт. FTP умеет upload и download. SMB поддерживает длительные подключения к общим файлам/принтерам и работает не только в Windows.

### HTTP и DHCP в сценариях

GET запрашивает ресурс; POST отправляет данные на обработку, часто при загрузке; PUT задаёт/заменяет ресурс по известному URI. HTTPS защищает HTTP с TLS; обычный HTTP не шифрует. В учебных вопросах HTTP/1.1 и HTTP/2 используют TCP для надёжной доставки; HTTP/3 использует QUIC поверх UDP.

DHCP автоматизирует адрес, маску, шлюз и DNS. Сервер UDP 67, клиент UDP 68. Домашний роутер обычно играет роль DHCP-сервера. Автоматический 169.254.x.x вместо ожидаемого адреса — признак, что клиент не получил аренду; это ещё не доказательство конкретной поломки сервера. TFTP использует UDP 69, в отличие от FTP.

## Полная цепочка веб-запроса, DNS и аренды DHCP

### От URL до страницы

В `http://www.cisco.com/index.html` схема — http, имя сервера — www.cisco.com, путь — /index.html. Браузеру нужен IP: сначала cache/DNS. Затем классический HTTP-клиент устанавливает TCP-соединение, отправляет GET с путём, получает status/headers/body, а браузер интерпретирует HTML. HTML — язык структуры документа, HTTP — протокол обмена; картинка может потребовать отдельного запроса. HTTPS добавляет TLS, который защищает передачу, но не гарантирует добросовестность сайта. HTTP/3 вместо TCP использует QUIC — поэтому проверяй версию в вопросе.

### DNS распределён, а не знает всё в одном месте

Иерархия: root → TLD (.com) → домен cisco.com → имя www.cisco.com. Authoritative server знает данные своей зоны; recursive resolver помогает клиенту получить ответ, используя другие серверы и cache. Ответы временно кэшируются по TTL; это экономит запросы, но устаревшая запись может сохраняться до истечения срока. В DNS-сообщении есть question, answer, authority и additional sections. A/AAAA содержат адрес, NS задаёт авторитетный сервер, MX — mail exchanger; имя почтового сервера затем тоже разрешается в IP.

`nslookup example.com` проверяет серверный DNS-ответ; `ipconfig /displaydns` показывает локальный кэш Windows. Если доступ по IP работает, а по имени нет, исследуй DNS, не объявляй сразу сломанным физический линк. Если имя вне зоны, сервер не обязан сразу отказывать: возможны рекурсия, forwarding или referral.

### DORA — почему нужны все четыре сообщения

Discover ищет DHCPv4-серверы; Offer предлагает адрес, маску, gateway, DNS и срок аренды. При нескольких Offer клиент выбирает один и отправляет Request с указанием предложения. ACK подтверждает аренду; NAK означает, что предложение недействительно и получение нужно начать заново. До истечения lease клиент запрашивает продление. IP не становится вечной собственностью устройства. Static полезен для предсказуемых адресов инфраструктуры, DHCP — для массовой управляемой настройки клиентов.

Начальный клиент без IPv4 использует 0.0.0.0 и broadcast; UDP 68 — клиент, 67 — сервер. Адрес 169.254.x.x после ожидания DHCP — повод проверить связь, VLAN, relay и доступность DHCP, а не доказательство единственной причины. DHCPv6 имеет другие имена сообщений; не переноси слово DORA как буквальные имена IPv6-пакетов.

### Почта, файлы и распределение ролей

Путь письма: sender client → SMTP server → SMTP server получателя → IMAP/POP3 клиент получателя. IMAP сохраняет серверный mailbox и синхронизирует папки; POP3 ориентирован на загрузку сообщений и может оставлять копии настройкой. Безопасные версии могут использовать TLS и другие порты, чем базовая таблица курса.

FTP: control channel остаётся для команд, data channel создаётся для передачи файла/списка. Active/passive отличаются установлением data connection; оба варианта могут загружать и скачивать. SMB включает создание/аутентификацию/закрытие сессий и управление доступом к файлам/принтерам. Samba позволяет участвовать Linux/Unix; протокол не ограничен Microsoft.

P2P-приложению нужны пользовательская часть и фоновая служба отдачи ресурсов. В hybrid P2P индекс может быть централизован, а сами файлы — на peers. Выделенный directory/tracker поэтому не обязательно превращает обмен файлов в обычный central file-server. В client/server направление upload/download не меняет роли: client инициирует запрос, server предоставляет сервис.

**Самопроверка без подсказок:** URL→DNS→TCP→HTTP; DNS TTL зачем? Почему DHCP Request после Offer? Кто выдаёт IP, кто ищет MAC? Чем IMAP отличается от SMTP? Почему upload не делает клиента сервером? Ответь своими словами до открытия вариантов.

## 16. Безопасность

## Различай термины

**Threat** — потенциальная угроза; **vulnerability** — слабое место; **exploit** — способ использовать его. Confidentiality/Integrity/Availability — конфиденциальность, целостность, доступность.

| Сценарий | Категория |
|---|---|
| Кража базы/секретных документов | information theft |
| Использование чужой личности/карты | identity theft |
| Удаление/подмена записей | data loss/manipulation |
| Перегрузка сайта до отказа | disruption of service / DoS |
| Сканирование сети перед атакой | reconnaissance |
| Неавторизованный вход | access attack |
| Перехват между сторонами | man-in-the-middle |

Virus внедряется в другой объект; worm самостоятельно распространяется; Trojan маскируется под полезное ПО; spyware собирает сведения. Вирус тоже размножается — неверно учить «вирусы не размножаются вообще».

Firewall фильтрует обмен; stateful inspection учитывает состояние соединений. IDS обнаруживает и сообщает, IPS может блокировать. DMZ изолирует публичные серверы от внутренней сети. Защита в несколько слоёв сочетает обновления, firewall, endpoint protection, сильные секреты, ограничение прав и backup.

## AAA

- Authentication: кто ты? Проверка личности.
- Authorization: что тебе можно? Права чтения/изменения.
- Accounting: что ты сделал? Учёт действий и событий.

## IOS security

`login block-for 30 attempts 2 within 10`: блокировать вход на 30 секунд после 2 неудач за 10 секунд. Не перепутай три числа.

`exec-timeout 5 0` завершает неактивный сеанс через 5 минут. Console и VTY защищаются отдельно. SSH предпочтительнее Telnet. Секреты по имени человека, даже с изменённым регистром, легко угадываются.

Физические угрозы: hardware — повреждение; environmental — температура/влажность; electrical — питание; maintenance — ошибки обслуживания.

## Дополнения по вопросам банка

### Узнавать угрозу по действию

Information theft — украли документы/базу; identity theft — выдают себя за другого, например оформляют кредит; data loss/manipulation — уничтожили/изменили записи; disruption of service — лишили законных пользователей доступа. Это последствия. Reconnaissance собирает карту систем и портов; access attack получает чужой доступ; DoS перегружает/нарушает сервис. Один инцидент может включать несколько стадий.

Virus связан с заражённой программой/объектом; worm распространяется самостоятельно через уязвимости; Trojan маскируется под полезную программу; spyware скрыто собирает сведения. Патчи закрывают уязвимости червей, антивирус помогает обнаруживать вредоносный код. Сам факт замедления не доказывает наличие worm без других признаков. Man-in-the-middle перехватывает/изменяет обмен между сторонами.

### AAA и фильтрация

Authentication — кто ты; authorization — что тебе разрешено; accounting — журнал твоих действий. Папка Read-only для всех и Edit только администраторам — authorization. Firewall ограничивает трафик; stateful inspection связывает ответы с существующими соединениями. Packet filtering может учитывать IP, протокол и транспортные порты; URL filtering — веб-адреса/категории. Современная application filtering распознаёт приложения, а не только номера портов, хотя старый вопрос банка упрощает это до портов.

DMZ размещает доступные извне серверы отдельно от внутренней сети. VPN обеспечивает защищённый удалённый туннель. Layered security — несколько рубежей защиты, например perimeter firewall, внутренний IPS и защита endpoints. Резервные копии нужны для восстановления; их тоже защищают паролями/правами и проверяют восстановление.

### SSH и физические угрозы

SSH TCP 22 шифрует вход и данные; Telnet TCP 23 — нет. Для IOS SSH нужны hostname, domain name, RSA keys, local user; на VTY — `login local` и `transport input ssh`. `login block-for 180 attempts 2 within 30` блокирует вход на 180 секунд после двух неудач за 30 секунд. `exec-timeout` ограничивает простой console/VTY. Личные имена вроде RobErT — слабые пароли даже со сменой регистра.

Environmental: температура/влажность; electrical: скачки напряжения/отключения; hardware: физические повреждения; maintenance: ошибки обращения, ESD, плохие кабели/маркировка, отсутствие запчастей. Технологическая уязвимость ОС отличается от неверной настройки ACL и недостатков политики безопасности.

## Защита: пропущенные темы курса и практический смысл

### Три вида слабостей и четыре вида ущерба

Технологическая слабость — дефект ОС/протокола/оборудования. Конфигурационная — неверная ACL, открытый ненужный сервис, слабый пароль. Слабость политики — отсутствующие или плохо продуманные правила доступа, обновлений и ответственности. Один инцидент может сочетать все три. Не называй любой протокол «всегда небезопасным»: например, приложение может использовать TLS, а версия и настройка имеют значение.

CIA помогает классифицировать ущерб: кража сведений нарушает confidentiality; подмена записей — integrity; перегрузка сервиса — availability. Identity theft выделяется использованием чужой личности, а не просто наличием чужого имени в украденной базе.

### Слои защиты и их роли

| Средство | Конкретная роль |
|---|---|
| VPN | Защищённый туннель удалённого доступа/между площадками |
| Firewall | Политика разрешения и запрета сетевого обмена |
| IPS | Анализ трафика с возможностью блокирования обнаруженной атаки |
| IDS | Обнаружение и оповещение; само по себе не равно блокированию |
| ESA / WSA | Фильтрация подозрительной почты / опасных веб-ресурсов |
| AAA server | Централизованная личность, права и учёт административного доступа |
| Endpoint protection | Антивирус/host IPS, обновления, firewall хоста и обученный пользователь |

DMZ позволяет публиковать нужные серверы отдельными правилами, не открывая всю внутреннюю сеть. Stateful firewall не обязан запрещать абсолютно все новые входящие подключения: правила могут явно разрешать публичную службу. Его отличие — учёт состояния соединения.

### Backups: четыре отдельных вопроса

**Frequency:** как часто сохранять полный backup и изменения. **Storage:** где хранить копию, включая отдельную площадку, чтобы один инцидент не уничтожил оригинал и копию. **Security:** кто имеет доступ, как защищены копия и ключи/пароли восстановления. **Validation:** проверить целостность и реально попробовать восстановление. Файл, который скопировали, но никогда не восстановили, ещё не доказывает рабочий план восстановления.

Обновления закрывают известные уязвимости, особенно важные для самостоятельного распространения worm. Стандартный образ ОС с разрешёнными приложениями облегчает управление, но после развёртывания тоже нуждается в патчах. Антивирусные определения обновляют обнаружение; они не заменяют исправление ОС.

### Hardening и Cisco AutoSecure

`auto secure` из privileged EXEC запускает помощник настройки защиты на поддерживаемом IOS. Он помогает, но не делает устройство неуязвимым; до применения в реальной сети нужно понимать, какие службы и доступ он изменит. Общие шаги: сменить заводские credentials, ограничить права, убрать ненужные службы, обновить ПО и обеспечить физическую защиту.

Физический план включает закрываемую серверную, контроль/журнал входов и камеры; кондиционирование — от перегрева, UPS/качественное питание — от electrical threats, ESD-защиту и маркировку — от maintenance mistakes.

### Почему каждая команда безопасности нужна

| Команда / место | Что делает | Чего не делает |
|---|---|---|
| security passwords min-length 10 / global | Требует минимальную длину для новых поддерживаемых паролей | Не делает угадываемое имя хорошим паролем и не заменяет существующие автоматически |
| login block-for 120 attempts 3 within 60 / global | Блокирует VTY-попытки на 120 секунд после 3 неудач за 60 секунд | Не блокирует весь IP-трафик и не защищает физический вход |
| exec-timeout 5 30 / line | Завершает сеанс после 5 минут 30 секунд простоя | Это не общий лимит длительности активной работы |
| login local / VTY | Проверяет локальную базу username | Не создаёт пользователя и не генерирует SSH keys |
| transport input ssh / VTY | Разрешает SSH вместо Telnet | Не включает шифрование открытого Telnet-сеанса |
| no ip http server / global | Выключает ненужный HTTP-сервер устройства | Не выключает автоматически отдельный HTTPS-сервер |

Службы сначала проверяют: `show ip ports all` на подходящем IOS-XE или `show control-plane host open-ports` на старом IOS. Отключают только ненужное, чтобы не потерять используемый способ управления. Проверка `show running-config | section line vty` показывает выбранные правила входа; затем сохраняют `copy running-config startup-config`.

### Исторический учебный пример и реальные настройки

В исходном курсе встречаются RSA 1024, MD5 и учебные пароли cisco/class. Это иллюстрации синтаксиса старой платформы, не современный эталон защиты. В рабочем устройстве выбирают поддерживаемые актуальные алгоритмы, SSHv2 и надёжные уникальные секреты; уже существующий конспект использует пример RSA 2048. Type 7 обратим, смена регистра имени не спасает слабый пароль. Длинная непредсказуемая passphrase помогает запоминанию без очевидных личных данных.

Практическая последовательность SSH: hostname → domain name → RSA keys → local username secret → VTY login local → transport input ssh; нужны также IP-доступность и разрешение соединения политикой. Проверь вход и права, закрытие неактивного сеанса и сохранение настроек. Изученные лабораторные цели не означают, что конкретные PT-активности уже выполнены.

### Разведка, доступ и DoS: не путать стадии

Разведка включает Internet queries (публичные сведения и DNS/регистрация), ping sweep (какие адреса отвечают) и port scan (какие службы доступны). Это сбор картины, а не доказанный взлом; те же средства используются администраторами при разрешённой диагностике.

Виды access attack: **password attack** пытается получить секрет подбором, кражей или перехватом; **trust exploitation** использует скомпрометированную доверенную систему/учётную запись, чтобы получить доступ к другой; **port redirection** использует перенаправление через уже захваченную систему для достижения ресурса, к которому напрямую путь ограничен; **man-in-the-middle** вмешивается в обмен сторон, читая или подменяя его. Не путай port redirection с обычным разрешённым NAT port forwarding: категория определяется не названием функции, а неразрешённым использованием.

DoS истощает ресурсы/нарушает сервис. DDoS имеет ту же цель, но трафик приходит из множества источников, часто с заражённых устройств. Много пакетов от одного компьютера — ещё не доказательство DDoS. Trojan определяется обманной маскировкой и не обязан сам размножаться; он может открыть backdoor или загрузить другой malware, включая worm.
