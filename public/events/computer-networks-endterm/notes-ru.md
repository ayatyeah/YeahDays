## 8. Сетевой уровень: как пакет попадает в другую сеть

**Главная мысль:** IP отвечает за адресацию и передачу пакета между сетями. Маршрутизатор выбирает следующий шаг по destination IP и таблице маршрутизации.

Путь данных: данные приложения → сегмент TCP/датаграмма UDP → пакет IP → кадр Ethernet → биты. Получатель разбирает оболочки в обратном порядке. На каждом маршрутизаторе старый кадр снимается и создаётся новый для следующего канала.

### Три характеристики IP

- **Connectionless:** перед отправкой IP не устанавливает соединение.
- **Best effort:** IP не гарантирует доставку, порядок и отсутствие дубликатов. Потерянный пакет сам не пересылает повторно.
- **Media independent:** IP может работать поверх Ethernet, Wi-Fi и других каналов.

Надёжность при необходимости обеспечивает TCP или приложение. «Ненадёжный» не означает «всегда теряет пакеты» — означает отсутствие гарантии и собственного восстановления.

### IPv4 и IPv6 headers

| Признак | IPv4 | IPv6 |
|---|---|---|
| Размер адреса | 32 бита | 128 бит |
| Основной заголовок | минимум 20 байт, длина может меняться | фиксированные 40 байт |
| Ограничение числа переходов | TTL | Hop Limit |
| Следующий протокол | Protocol | Next Header |
| Проверка основного заголовка | Header Checksum | такого поля нет |

Protocol в IPv4: ICMP = 1, TCP = 6, UDP = 17. TTL/Hop Limit уменьшается на маршрутизаторах; при нуле пакет отбрасывается. Source/Destination IP обычно сохраняются по пути, если нет NAT; MAC-адреса меняются при переходе на другой канал.

**MTU** — максимальный размер пакета, переносимого данным каналом. IPv4 допускает фрагментацию при соответствующих условиях; IPv6-маршрутизатор пакеты не фрагментирует, а сообщает источнику Packet Too Big. Источник должен подстроить размер.

### Локальный адресат или шлюз

ПК 192.168.1.10/24 отправляет данные на 192.168.1.20: сеть та же, кадр адресуется MAC получателя.

Если получатель 192.168.2.20: сеть другая, кадр адресуется MAC шлюза, например 192.168.1.1. При этом destination IP остаётся 192.168.2.20. Ошибка шлюза часто даёт ситуацию «локальная сеть работает, удалённые сети нет».

Таблица маршрутизации содержит connected, static и dynamic routes. Выбирается самый длинный совпавший префикс. Default route — маршрут последней надежды: IPv4 `0.0.0.0/0`, IPv6 `::/0`. В IOS `C` означает connected, `L` — local, `S` — static, `O` — OSPF.

Проверка: IOS `show ip route`; Windows `route print` или `netstat -r`.

**Ответ на открытый вопрос:** IP предоставляет логическую адресацию и маршрутизацию. Он работает без установления соединения, обеспечивает best-effort доставку и не зависит от среды передачи; подтверждения и повторные передачи при необходимости выполняются выше.

## 9. ARP и ND: как найти MAC

**Главная мысль:** знание IP ещё не даёт destination MAC для Ethernet-кадра.

### ARP для IPv4

1. Отправитель определяет, кто следующий сосед: конечный локальный узел или шлюз.
2. Ищет соответствие IPv4→MAC в ARP cache.
3. Если записи нет, отправляет ARP Request на `FF:FF:FF:FF:FF:FF`.
4. Владелец запрошенного IPv4 отвечает своим MAC, обычно unicast.
5. Соответствие временно сохраняется в RAM.

`arp -a` показывает кэш на ПК; `show ip arp` — на Cisco; `arp -d *` очищает динамический кэш на Windows. ARP не ищет MAC удалённого интернет-сервера через все маршрутизаторы: для удалённой сети нужен MAC локального шлюза.

Не путай две таблицы:

| Таблица | Соответствие |
|---|---|
| ARP | IPv4 → MAC |
| MAC address table коммутатора | MAC → порт/VLAN |

Коммутатор обучается по **source MAC**, пересылает по **destination MAC**. Unknown unicast и broadcast рассылаются в пределах VLAN по всем подходящим портам, кроме входного.

### Neighbor Discovery для IPv6

IPv6 не использует ARP и broadcast. ICMPv6 ND включает:

- **NS / NA:** Neighbor Solicitation / Advertisement — поиск соседа и разрешение IPv6→MAC.
- **RS / RA:** Router Solicitation / Advertisement — запрос и объявление параметров маршрутизатора/сети.
- **DAD:** проверка уникальности адреса, использующая NS.

ARP spoofing/poisoning подменяет IP→MAC и может перенаправить трафик через атакующего.

**Проверь себя:** пакет в другую сеть имеет destination IP удалённого хоста, а кадр — destination MAC локального шлюза.

## 10. Настройка Cisco IOS

### Режимы и память

| Приглашение | Режим | Как попасть |
|---|---|---|
| `R1>` | user EXEC | начальный вход |
| `R1#` | privileged EXEC | `enable` |
| `R1(config)#` | global configuration | `configure terminal` |
| `R1(config-if)#` | interface configuration | `interface ...` |
| `R1(config-line)#` | line configuration | `line console 0` / `line vty 0 4` |

`exit` — назад на один уровень; `end` или Ctrl-Z — в privileged EXEC. `?` — контекстная справка; Tab — дополнение команды.

**RAM:** running-config, ARP cache, routing table; данные теряются при отключении питания. **NVRAM:** startup-config. **Flash:** обычно образ IOS. Настройки running-config действуют сразу, но для сохранения после перезагрузки нужно `copy running-config startup-config`.

### Учебный пример настройки

Значения в угловых скобках ниже надо заменить; названия интерфейсов зависят от устройства.

```text
enable
configure terminal
hostname R1
enable secret <strong-enable-secret>
service password-encryption
banner motd #Authorized access only#
line console 0
 password <console-password>
 login
 exec-timeout 5 0
 exit
interface gigabitEthernet 0/0
 description LAN
 ip address 192.168.10.1 255.255.255.0
 ipv6 address 2001:db8:10::1/64
 no shutdown
 exit
ipv6 unicast-routing
end
copy running-config startup-config
```

`no shutdown` административно включает интерфейс. `description` — комментарий. `ipv6 unicast-routing` включает пересылку IPv6 между интерфейсами.

На L2-коммутаторе IP для управления задают SVI, например `interface vlan 1`, а шлюз — `ip default-gateway 192.168.10.1`. Это не превращает L2-коммутатор в маршрутизатор. Для работы SVI также нужны соответствующие условия активности VLAN/портов.

### SSH

```text
configure terminal
ip domain-name lab.example
username admin secret <strong-user-secret>
crypto key generate rsa
! При запросе размера ключа в учебной лаборатории выбери поддерживаемое значение, например 2048.
ip ssh version 2
line vty 0 4
 login local
 transport input ssh
 exec-timeout 5 0
end
copy running-config startup-config
```

Hostname уже задан. Нужны IP-доступность устройства, пользователь и RSA keys. `login local` использует локальную базу пользователей. `transport input ssh` разрешает SSH на VTY. SSH шифрует сеанс, Telnet — нет.

`service password-encryption` в классическом IOS скрывает открытые пароли слабой обратимой Type 7; это не полноценная защита секретов и не шифрование сетевого трафика. См. [Cisco о хранении секретов](https://www.cisco.com/c/en/us/about/trust-center/resilient-infrastructure/protecting-secrets.html).

### Что проверять

- `show ip interface brief` — IPv4 и Status/Protocol; рабочее состояние обычно up/up.
- `show ipv6 interface brief` — IPv6 интерфейсов.
- `show running-config` — действующие команды.
- `show startup-config` — сохранённая конфигурация.
- `show ip route` — маршруты.
- `ping` — достижимость; `traceroute` — промежуточные переходы.

## 11. IPv4 и подсети

**Главная мысль:** маска делит 32-битный адрес на network и host части. Адрес сети получается побитовым AND адреса и маски.

### Таблица, которую стоит выучить

| Префикс | Маска | Размер блока | Пригодных хостов в обычной LAN |
|---|---|---:|---:|
| /24 | 255.255.255.0 | 256 | 254 |
| /25 | 255.255.255.128 | 128 | 126 |
| /26 | 255.255.255.192 | 64 | 62 |
| /27 | 255.255.255.224 | 32 | 30 |
| /28 | 255.255.255.240 | 16 | 14 |
| /29 | 255.255.255.248 | 8 | 6 |
| /30 | 255.255.255.252 | 4 | 2 |

Если h = 32 − prefix, всего адресов 2^h, обычно хостов 2^h−2. Отнимаются network address и broadcast. /31 для point-to-point и /32 — исключения, к которым нельзя механически применять эту формулу.

### Как решить задачу за минуту

Адрес `192.168.10.77/28`:

1. /28 → маска .240, размер блока 256−240=16.
2. Границы: 0,16,32,48,64,80… Число 77 лежит между 64 и 79.
3. Network: `192.168.10.64`.
4. Broadcast: `192.168.10.79`.
5. Хосты: `.65`–`.78`, всего 14.

Пример `/22`: `172.16.16.0/22` имеет маску 255.255.252.0. Шаг третьего октета 4, диапазон 16–19. Broadcast `172.16.19.255`, хостов 1022.

### Число подсетей и VLSM

Для N одинаковых подсетей нужно b бит, чтобы 2^b ≥ N. Пять сетей: 2²=4 мало, 2³=8 достаточно → занять 3 бита. Из /24 получим /27.

VLSM позволяет разные размеры подсетей. Например внутри /24 нужны 100, 50 и 20 хостов: /25 (126), /26 (62), /27 (30). Размещаем от большей к меньшей: `.0/25`, `.128/26`, `.192/27`. Блоки должны быть выровнены и не пересекаться.

### Специальные диапазоны

| Диапазон | Назначение |
|---|---|
| 10.0.0.0/8 | private |
| 172.16.0.0/12 | private: 172.16–172.31 |
| 192.168.0.0/16 | private |
| 127.0.0.0/8 | loopback, типичный пример 127.0.0.1 |
| 169.254.0.0/16 | link-local, часто результат неудачного DHCP |
| 224.0.0.0/4 | multicast |
| 255.255.255.255 | limited broadcast |

Не вся сеть 172/8 частная. Broadcast конкретной подсети — последний её адрес, а не обязательно адрес с последним октетом 255.

## 12. IPv6

128 бит записываются восемью группами по 16 бит, в hex. Пример: `2001:0db8:0000:abcd:0000:0000:0000:0001` → `2001:db8:0:abcd::1`.

Правила: ведущие нули внутри группы можно убрать; одну последовательность нулевых групп — заменить `::`. Использовать `::` дважды нельзя. При равных самых длинных нулевых последовательностях стандартная запись сокращает первую.

### Типы адресов

- **GUA:** глобальный unicast; в типичных учебных примерах 2000::/3.
- **LLA:** link-local FE80::/10; только один канал, через router не пересылается.
- **Loopback:** ::1/128.
- **Unspecified:** ::/128 — отсутствие назначенного адреса в соответствующих процедурах.
- **Multicast:** FF00::/8; FF02::1 — все узлы, FF02::2 — маршрутизаторы данного канала.
- **Anycast:** один unicast-адрес назначен нескольким интерфейсам, доставка ближайшему по метрике маршрутизации.

**Broadcast в IPv6 отсутствует.** Не путай link-local и private IPv4: это разные механизмы и области действия.

### Префиксы и подсети

Для обычной LAN применяется /64. В `2001:db8:cafe:1111:2222:3333:4444:5555/64` первые четыре группы — префикс, последние четыре — interface ID. Если провайдер дал /48, четвёртая группа (`1111`) — 16-битный subnet ID. Это даёт 2^16 = 65536 подсетей /64.

### Как назначается адрес

| Метод | Адрес | Другие параметры |
|---|---|---|
| SLAAC | хост формирует по префиксу RA | из RA, по поддерживаемым возможностям |
| SLAAC + stateless DHCPv6 | формирует сам | дополнительные параметры, например DNS, через DHCPv6 |
| Stateful DHCPv6 | выдаёт DHCPv6 server | DHCPv6 |

Default gateway обычно узнают из RA, а не DHCPv6. RS — запрос маршрутизаторам, RA — ответ/объявление маршрутизатора. DAD проверяет, не занят ли адрес.

EUI-64: MAC делится пополам, вставляется FFFE, инвертируется U/L-бит. Другой вариант — сгенерированный interface ID. Не все устройства используют MAC для IPv6-адреса.

Совместная работа: dual stack — два стека; tunneling — пакет внутри пакета; translation — преобразование между протоколами.

## 13. ICMP, ping и traceroute

ICMP сообщает об ошибках IP и помогает диагностике. Он не гарантирует доставку и не заменяет TCP.

**ping:** Echo Request → Echo Reply. Позволяет оценить достижимость и round-trip time (RTT). Ответ loopback подтверждает локальный стек; ответ шлюза — достижимость шлюза. Ни один из них сам по себе не доказывает доступ ко всему интернету.

**traceroute / tracert:** пробные пакеты с TTL/Hop Limit 1,2,3… Маршрутизатор, у которого значение исчерпалось, отвечает Time Exceeded. Так видны промежуточные hop. Конкретный транспорт проб зависит от реализации.

В IOS `!` — ответ, `.` — таймаут, `U` — unreachable. Фильтрация ICMP и ограничение частоты ответов могут скрыть рабочий узел: один `*` в трассировке не равен доказанной поломке.

Порядок диагностики: IP/маска → loopback → локальный сосед/шлюз → удалённый IP → доменное имя. Если IP работает, имя нет — проверь DNS. `ipconfig`, `nslookup`, `ping`, `tracert` отвечают на разные вопросы.

Ловушка: «ICMP code 0» без типа недостаточно. У ICMPv4 Type 3/Code 0 — network unreachable; у Echo Reply Type 0/Code 0 — успешный ответ. В IPv6 неизвестный Next Header сообщается через Parameter Problem; не переносите таблицу кодов IPv4 на IPv6. [RFC 4443](https://datatracker.ietf.org/doc/html/rfc4443).

## 14. TCP и UDP

**Главная мысль:** IP доводит пакет до устройства, транспортный уровень помогает доставить данные нужному приложению и различать разговоры.

| Свойство | TCP | UDP |
|---|---|---|
| Соединение | устанавливается | не устанавливается |
| Доставка | ACK и повторные передачи | гарантии и повторов нет |
| Порядок | восстанавливается | UDP не упорядочивает |
| Управление потоком | есть | нет |
| Заголовок | минимум 20 байт | 8 байт |
| Примеры курса | HTTP, FTP, SMTP | VoIP, TFTP, DNS-запросы |

UDP checksum умеет обнаруживать повреждение; отсутствие надёжности не означает отсутствие проверки. Для IPv6 UDP checksum в общем случае обязателен, с узкими специальными исключениями. [RFC 8200](https://datatracker.ietf.org/doc/html/rfc8200).

### Порты и sockets

Socket = IP:port, например `192.168.1.10:49152`. Для различения обмена учитываются адреса, порты и транспортный протокол. Клиент использует временный порт, сервер — известный порт службы.

- 0–1023: well-known/system.
- 1024–49151: registered/user.
- 49152–65535: dynamic/private.

Запрос HTTP: клиент `10.1.1.10:49152` → сервер `10.1.1.254:80`; в ответе роли source/destination меняются.

### TCP handshake и завершение

Открытие: SYN → SYN+ACK → ACK. SYN синхронизирует начальные номера, ACK подтверждает. Типичное закрытие: FIN → ACK, затем FIN → ACK в другом направлении; сообщения могут объединяться, поэтому «всегда ровно четыре» слишком строго.

Sequence number — номер байта в потоке. ACK — номер следующего ожидаемого байта. Если приняли байты 1–4500, ACK = 4501, а не 4500.

Receive window сообщает, сколько данных получатель готов принять: это **flow control**. Sliding window позволяет послать несколько сегментов без ожидания ACK после каждого. **Congestion control** отдельно реагирует на перегрузку сети и уменьшает объём неподтверждённых данных.

UDP хорош, когда небольшая задержка важнее повторной передачи старых данных или восстановление выполняет само приложение. Это не утверждение, что любое видео всегда использует UDP: потоковое видео может идти по TCP/QUIC.

## 15. Прикладной уровень

В TCP/IP application layer объединяет OSI application, presentation и session. Presentation связана с форматами, кодированием/сжатием; session — с управлением диалогом; application — с сетевыми сервисами приложений.

### Протоколы и порты

| Сервис | Порт в базовых примерах | Для чего |
|---|---|---|
| FTP | TCP 21; data TCP 20 в active mode | передача файлов |
| SSH | TCP 22 | защищённое управление |
| Telnet | TCP 23 | незашифрованное управление |
| SMTP | TCP 25 | отправка/пересылка почты |
| DNS | UDP/TCP 53 | записи имён |
| DHCPv4 | UDP 67 server, 68 client | выдача IP-настроек |
| TFTP | UDP 69 для начального запроса | простой перенос файлов |
| HTTP | TCP 80 в классической модели | веб |
| POP3 | TCP 110 | получение почты |
| IMAP | TCP 143 | серверный почтовый ящик |
| HTTPS | 443 | защищённый веб |
| SMB | TCP 445 | файлы и принтеры |

Это учебная таблица: существуют защищённые почтовые порты, пассивный FTP и HTTP/3 поверх QUIC/UDP. Для MCQ ориентируйся на конкретную формулировку.

### DNS

A → IPv4, AAAA → IPv6, MX → mail exchanger, NS → authoritative nameserver, CNAME → alias. `.com` — top-level domain. DNS-сервер не обязан отказывать только потому, что имя не в его зоне: может использовать рекурсию/пересылку. `nslookup` проверяет разрешение имени; DNS работает и по UDP, и по TCP.

### DHCP

DORA: Discover → Offer → Request → Acknowledge. Клиент без адреса ищет сервер broadcast-сообщением. DHCP выдаёт адрес на время аренды и параметры сети. На домашней сети эту роль часто выполняет роутер. Адрес 169.254.x.x вместо ожидаемого DHCP-адреса — повод проверить доступность сервера.

### HTTP и почта

GET получает ресурс; POST отправляет данные; PUT создаёт/заменяет ресурс по указанному адресу. HTTPS использует TLS для защиты HTTP.

SMTP отправляет почту, POP3 получает её на клиент, IMAP поддерживает централизованное хранение и синхронизацию. POP3 может оставлять копии, поэтому «всегда удаляет с сервера» неверно.

FTP имеет control и data connection, умеет upload/download. SMB предоставляет совместные файлы/принтеры и длительные сеансы; не ограничен Windows.

Client/server: клиент инициирует запрос, сервер предоставляет сервис. При upload ПК всё ещё клиент. P2P: узел может быть и клиентом, и сервером; выделенный сервер не обязателен.

## 16. Безопасность

### Различай термины

**Threat** — потенциальная угроза; **vulnerability** — слабое место; **exploit** — способ использовать его. Confidentiality/Integrity/Availability — конфиденциальность, целостность, доступность.

| Сценарий | Категория |
|---|---|
| Кража базы/секретных документов | information theft |
| Использование чужой личности/карты | identity theft |
| Удаление/подмена записей | data loss/manipulation |
| Перегрузка сайта до отказа | disruption of service / DoS |
| Сканирование сети перед атакой | reconnaissance |
| Неавторизованный вход | access attack |
| Перехват между сторонами | man-in-the-middle |

Virus внедряется в другой объект; worm самостоятельно распространяется; Trojan маскируется под полезное ПО; spyware собирает сведения. Вирус тоже размножается — неверно учить «вирусы не размножаются вообще».

Firewall фильтрует обмен; stateful inspection учитывает состояние соединений. IDS обнаруживает и сообщает, IPS может блокировать. DMZ изолирует публичные серверы от внутренней сети. Защита в несколько слоёв сочетает обновления, firewall, endpoint protection, сильные секреты, ограничение прав и backup.

### AAA

- Authentication: кто ты? Проверка личности.
- Authorization: что тебе можно? Права чтения/изменения.
- Accounting: что ты сделал? Учёт действий и событий.

### IOS security

`login block-for 30 attempts 2 within 10`: блокировать вход на 30 секунд после 2 неудач за 10 секунд. Не перепутай три числа.

`exec-timeout 5 0` завершает неактивный сеанс через 5 минут. Console и VTY защищаются отдельно. SSH предпочтительнее Telnet. Секреты по имени человека, даже с изменённым регистром, легко угадываются.

Физические угрозы: hardware — повреждение; environmental — температура/влажность; electrical — питание; maintenance — ошибки обслуживания.
