Аян: Один клик по сайту, а служб как в министерстве. Кто тут вообще за что отвечает?

Порт Петрович: Прикладной уровень TCP/IP объединяет функции трёх верхних уровней OSI. Application связан с сетевыми сервисами приложений. Presentation — с форматом данных, кодированием и сжатием. Session — с управлением диалогом. Теперь проследим практическую цепочку: устройство получает настройки, находит адрес по имени, открывает веб-соединение или отправляет почту. Для каждой задачи существует свой протокол, и их обязанности нельзя подменять друг другом.

Арпи: Арпи, узнай адрес сервиса. Только DNS спроси, а не каждого прохожего!

Порт Петрович: DNS сопоставляет имена с записями. A содержит IPv4, AAAA — IPv6, MX указывает mail exchanger, NS — авторитетный сервер имён, CNAME — псевдоним. Домен com — top-level domain. Если имя не входит в зону сервера, это не значит, что он обязан сразу отказать: возможны рекурсия или пересылка запроса. Для проверки используй nslookup. DNS работает и по UDP, и по TCP на порту 53, поэтому ответ «DNS — только UDP» неверен.

Аян: У меня нет адреса. Сервер предлагает аренду. Надеюсь, без залога за роутер.

Порт Петрович: DHCPv4 выдаёт адрес и параметры сети на время аренды. Запомни DORA: Discover, Offer, Request, Acknowledge. Клиент без адреса начинает с широковещательного поиска сервера. Сервер предлагает конфигурацию, клиент запрашивает выбранное предложение, сервер подтверждает. В домашней сети эту роль часто выполняет роутер. Серверный порт UDP 67, клиентский 68. Если вместо ожидаемого адреса появился 169.254, это повод проверить доступность DHCP, а не считать, что нужная настройка успешно получена.

Аян: Нажал GET, потом POST, потом PUT. Что я сейчас получил, отправил и заменил?

Порт Петрович: HTTP задаёт взаимодействие с веб-ресурсами. GET получает ресурс. POST отправляет данные на обработку. PUT создаёт или заменяет ресурс по указанному адресу. HTTPS защищает HTTP с помощью TLS. В классической учебной модели HTTP использует TCP 80, HTTPS — порт 443. Но существуют современные варианты: HTTP третьей версии работает поверх QUIC и UDP. В тестах внимательно читай, спрашивают ли базовую модель или конкретную версию протокола.

Арпи: Я попросил SMTP скачать почту. Он сказал: я вообще-то в другую сторону работаю.

Порт Петрович: SMTP отправляет и пересылает почту, в базовой таблице порт 25. POP3 получает письма на клиент, базовый порт 110. IMAP поддерживает централизованное хранение и синхронизацию ящика, базовый порт 143. Не учи, что POP3 всегда удаляет письмо с сервера: он может оставлять копии. Существуют защищённые почтовые порты, поэтому числа на экране относятся к базовым примерам курса. Главное различие — отправка, получение или синхронизация.

Аян: Файл, принтер и удалённая консоль. Петрович открыл три разных окошка обслуживания.

Порт Петрович: FTP использует отдельные управляющее и data-соединения и поддерживает загрузку в обе стороны. Управление — TCP 21; TCP 20 связан с передачей данных в active mode. В passive mode схема другая. TFTP — простой перенос файлов, UDP 69 используется для начального запроса. SMB предоставляет общие файлы и принтеры, работает с длительными сеансами и не ограничен Windows; базовый порт TCP 445. Для управления устройствами SSH использует TCP 22 и шифрование, Telnet — TCP 23 без шифрования.

Аян: Я загрузил файл на сервер и объявил себя сервером. Корона почему-то не подошла.

Порт Петрович: В модели client-server клиент инициирует запрос, сервер предоставляет сервис. Если ПК загружает файл на сервер, он всё ещё клиент: направление передачи данных не меняет роль. В peer-to-peer узел может одновременно запрашивать и предоставлять ресурсы; выделенный сервер не обязателен. Проверь себя: получение адреса — DHCP, разрешение имени — DNS, защищённый веб — HTTPS, отправка почты — SMTP. Эти протоколы решают разные задачи и часто работают последовательно в одном пользовательском действии.
